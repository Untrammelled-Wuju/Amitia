# U-Ai Workbench 第 57 轮：工作树元数据崩溃一致性

## 研发范围

从第 56 轮累计源码继续。重点处理 Coding Agent 工作树释放时的任务绑定与审批检查点的失效顺序、持久化目录落盘、元数据文件权限校验。本轮不新增独立 Git 引擎、不更改发布版本、不修改既有数据库迁移。

## 实际修改

1. 释放任务绑定时，先验证并失效旧审批检查点，再删除绑定。检查点失效失败则保持绑定，防止重启后旧审批在重新绑定时被复用。
2. 绑定、检查点与合并审计原子替换后，在支持的 Unix 系统上同步父目录。失效检查点、删除绑定后也执行目录同步；Windows 目录同步遵循原项目跨平台策略跳过，不承诺其具有相同的掉电持久性保证。
3. 本地读取绑定、检查点与合并审计时，Unix 系统拒绝其他用户可访问的权限模式。此检查仅约束本地元数据文件权限，不能代替系统级授权或进程沙盒。
4. 增加真实 Git 仓库故障注入与恢复测试：检查点路径被符号链接替换时释放必须失败且保留绑定；正常恢复后释放成功；重新实例化 Manager 仍能读取检查点；权限过宽的合法记录必须拒绝。
