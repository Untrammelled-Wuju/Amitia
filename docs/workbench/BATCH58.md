# U-Ai Workbench 第 58 轮：待决 Git 合并与检查点恢复围栏

## 修改范围

沿用第 57 轮累计源码。针对 Git 快进合并已生成 `pending` 审计但最终结果尚未落盘的恢复窗口，统一收口工作树释放、删除、检查点重建、测试和审批的并发行为。复用原有 `.merges` 跨进程文件锁及审计记录，不更改数据库迁移、发布版本和既有 Git Engine。

## 已实现

1. `Release` 在持有工作树测试锁、仓库分配锁的同时取得合并锁，确认没有待决审计后才失效检查点和释放绑定，避免合并中途删除恢复证据。
2. `Remove` 在删除工作树前取得合并锁，检查待决审计；即使原绑定意外缺失，也不能删除处于待决状态的来源工作树。
3. `PrepareCheckpoint`、`RunCheckpointTest`（开始和完成两个写入阶段）、`ApproveCheckpoint`、`InvalidateCheckpoint` 均在原有合并锁下拒绝待决审计，避免旧审计需要的测试/审批材料被覆盖。
4. 待决审计的读取失败或内容损坏时拒绝清理，保留绑定与检查点；正常完成或经过审计对账恢复为 `applied` 后允许既有绑定清理流程继续。
5. 提取独立的待决合并围栏，保持工作树 Manager、合并审计和检查点模块的职责边界。

## 本轮实际验证

- 对真实临时 Git 仓库构造待决合并，验证释放、失效、重新测试、重新审批均拒绝，并确认检查点和任务绑定未修改。
- 模拟快进合并已生效但审计仍为待决，重建 Manager 后恢复 `applied` 审计，并正常释放绑定。
- 删除绑定模拟非正常遗留记录，验证 `Remove` 仍拒绝删除待决来源工作树。
- 篡改待决审计文件，验证清理操作在文件损坏时拒绝且不丢失绑定。
- 持有合并锁模拟跨进程进行中的合并，验证释放请求按调用方截止时间失败而不改变状态。
- Git Worktree 包级 Go race 回归及 Windows/macOS/Linux ARM64/Android ARM64 目标交叉编译通过。
