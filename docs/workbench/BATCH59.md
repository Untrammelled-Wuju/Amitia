# U-Ai Workbench 第 59 轮：Worktree 重新绑定的恢复证据围栏

## 实施范围

沿用第 58 轮累计源码，处理异常中断后旧工作树被再次分配时可能破坏合并恢复证据的问题。仅调整现有 Git Worktree Manager 的 `Bind` 与 `EnsureTask`，不新增执行引擎、不变更迁移、不改变 HTTP 协议和发布版本。

## 源码修复

1. `Bind` 在仓库分配锁内额外获取与 Git 合并、清理共用的跨进程合并锁，确保重新绑定期间不会与待决合并交错执行。
2. 对尚未绑定的受管 Worktree，执行分配前检查持久化的合并审计及审批检查点；任意已有合并审计都禁止跨任务重新绑定，孤儿检查点要求先处理恢复证据。审计格式损坏时拒绝分配。
3. `EnsureTask` 的自动创建、绑定与已有任务恢复路径同样在跨进程合并锁下运行，确保自动分配不绕过审计保护；仍支持同一任务幂等重试。
4. 正常释放且没有剩余审计、检查点的工作树仍可再次绑定；需要保留已完成合并审计的任务应创建新的 Worktree。

## 本轮验证

- 在真实临时 Git 仓库验证孤儿待决审计、已恢复的成功审计、孤儿检查点及损坏审计不能被新任务绑定覆盖。
- 验证持有合并锁时，手动绑定与自动分配均在截止时间返回，而不是绕过锁创建绑定或新工作树。
- 验证正常释放后的无审计工作树可以被重新绑定，并保持现有 `EnsureTask` 并发幂等行为。
- 使用 `GO111MODULE=off go test -race -json -count=1 -timeout=180s` 运行整个 `gitworktree` 包，114 个用例通过事件、1 个包级通过事件、0 个失败事件。
- `GO111MODULE=off go vet .` 通过；Windows amd64、macOS amd64、Linux arm64、Android arm64 目标的包级测试交叉编译通过。
