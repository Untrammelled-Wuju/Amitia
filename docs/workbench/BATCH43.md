# U-Ai Workbench Batch 43：Coding Agent 终态回报、证据投影与父子结果对账

## 研发目标

以第 42 轮完整累计源码为基础，收敛从子 Agent 完成信号到父 Agent 任务结果、测试证明及人工合并资格的整条证据链。本轮研发范围估算目标 90%，并非生产上线验收达到 90%。

## 实现

- 在协调器处理子任务终态回报前，校验 Assignment 身份、绑定的 Child Interaction ID 和合法终态。只有重复的同身份、同状态回报允许幂等返回，冲突回报不能覆盖已完成状态。
- 对终态 Assignment 的 Child Interaction 读取增加状态一致性检查，并使用复制后的绑定身份核对来源 Space、Conversation、Character 与 RequestID，拒绝将跨任务或已改变状态的子任务结果透传给父 Agent。
- Coding Worker 测试投影新增摘要、测试启动时间；父 Agent 门禁要求测试配置、完整修订哈希、退出码、输出摘要、启动时间全部满足约束。不把终端正常退出当作经过验证的测试。
- 合并资格仅在 `not_attempted` 的明确审计状态开放；审计状态空值、未知值、正在对账及结果不一致时均拒绝。若任务终端仍有未验证的活动进程，显示需要人工审查的阻断状态。
- 扩展现有 Go 原始源码链接隔离回归脚本，涵盖终态跨任务回报、重复/冲突回报、篡改测试证据、终端活动残留、未知合并审计和子任务结果状态不一致。

## 测试范围与限制

- 使用 Go 1.23.2 + `-race` 对可独立测试的 interaction 原始源码进行隔离合同桩回归；同时执行 Worktree 真实 Git race 回归及终端、Web 现有定向门禁。
- 单独的 Go 语法解析及交叉编译只证明相应编译范围，不视为完整服务级类型检查。
- Go 1.26.1 完整后端、真实认证 HTTP、父子任务全链路实际执行、Flutter/Electron 以及真机 CDP/Device Mesh 仍须进行生产验收。
- 不自动提交或推送 Git，不更改已有构建产物、配对数据、应用端口及发布配置。
