# U-Ai Workbench Batch 37：终端输出字节游标协议联调修复

上一轮已实现 WebSocket 取消与握手超时。此轮聚焦 WebSocket 和 HTTP 轮询同时交付输出分片、恢复游标重叠与终端输出环形缓冲溢出时的**字节一致性**，不增加另一套终端或工作树管理器。

## 改动

- 后端 `outputBuffer` 返回明确的 `fromCursor` 与结束 `cursor`，包括未来游标钳制、分页及溢出截断场景；`Snapshot` 的 HTTP/WS 两条路径使用同一数据协议。
- 客户端以原始 Base64 字节数校验游标区间。重复旧分片忽略，重叠分片跳过已处理的前缀；不使用 JS 字符串长度计算 UTF-8 游标。
- 未解释的输出缺口拒绝追加，允许被服务端明确标记为 `truncated` 的缓冲区截断并提示用户；同时避免对重叠快照重复显示截断通知。
- 兼容老版本后端没有 `fromCursor` 的响应，以字节数倒推起始位置；错误或超限 Base64 数据拒绝进入渲染器。
- Flutter 终端快照解析校验 `fromCursor`，输出缓冲区支持重叠分片去重；恢复任务终端时校验当前任务身份，防止同一对话串绑；移动端页面销毁仅断开视图，不再隐式杀死后台长任务，明确点击“结束”才关闭远端终端。
- 增加 Go 缓冲区重播测试、真实 TS 源码隔离运行测试及 Vue/Vitest 回归用例；纳入工程定向验收门禁。

## 验收边界

Go buffer 的 `-race` 定向测试和 Node 实际 TS 转译执行可在 Go1.23 下隔离执行；完整 Go1.26.1 编译、已认证服务运行、Electron/Flutter/Windows ConPTY、Android/iOS 仍需对应正式工具链及真机验收。这些隔离测试不代表完整运行时已通过。
