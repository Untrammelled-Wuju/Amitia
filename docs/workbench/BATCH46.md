# Workbench 第 46 轮：浏览器控制权代次与 Device Mesh 信任重验证

本轮以第 45 轮累计源码为基线，围绕同一 Chromium 页面的控制权安全开展源码实施。

- Browser 控制许可现为每次成功申请生成独立随机 `leaseId`。续租和显式释放必须带上当前许可的 `leaseId`；同一用户旧页面迟到的释放或续租不能修改新一代许可。读取状态可向原控制者返回现有 `leaseId`，但权限变化后不能继续导出令牌。
- 浏览器人工输入入口在操作时再次核验认证主体和 Workbench 浏览器控制权限，不能仅凭之前取得过租约继续修改页面。
- Web/Electron 浏览器工作台保存和传递当前令牌；页面停用时释放捕获的旧代次；已取消申请的迟到响应会尝试只释放本次代次；释放后的迟到续租不得重新点亮控制状态。
- Flutter 浏览器工作台也将令牌与会话、Tab、设备和异步请求代次绑定。切换页面、后台和销毁时只释放原代次；跨设备观察仍维持只读。
- Device Mesh 的云端观察网关在目标返回后重新核验调用设备和目标设备的信任；目标 Runtime 在采集结果后重读设备凭据，拒绝调用期间已过期或变更的配对身份。

测试边界：Go Browser 原源码安全测试由隔离 Browser 契约桩链接并启用 `-race`；Web 浏览器控制和视图生命周期使用真实 Vue script 转译与异步桩；Flutter 和 Device Mesh 路由新增/更新源码结构检查；Go 语法检查并非完整工程编译。Chromium/CDP、真实 Gin HTTP、云端配对与 Android/iOS Release 构建仍需实际运行验证。
