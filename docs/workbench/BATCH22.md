# 第 22 轮 — 任务终端主动撤销与有界输出校验

## 实际实施

- `workbenchterminal/task_watchdog.go` 在独立定期检查任务绑定；只处理具有受检任务身份的终端，明确 `ErrTaskBinding` 或非法绑定才终止进程，暂时性仓库错误不销毁已有会话。
- `manager.go` 创建任务终端时保存 `conversationID`，避免后台巡检必须从包含冒号的 owner 字符串中猜测身份；拒绝缺失/非法对话 ID。
- `task_verification.go` 区分撤销与暂时不可用，任务校验失败仍禁止当前 API/WS 操作。终端列表会排除校验未通过的会话。
- `export.go` 在原有 256 KiB 有界输出的基础上增加读取时间、启动时间、保留字节数和 **保留字节** SHA-256 摘要；摘要不覆盖被淘汰的历史输出，不能证明运行了什么命令或测试通过。
- 协议 Schema、Web 数据类型、导出警告与后端同步更新。所有改动保持独立模块文件。

## 验证与不足

- Go 核心模块隔离测试 `go test -race -count=1 ./...` 通过，包括后台撤销、普通会话隔离、暂时性错误、非法任务绑定、有界导出及摘要一致性。
- Go 修改文件完成 gofmt 与独立语法解析；终端客户端脚本完成 TypeScript 转译检查；JSON Schema 结构与正反例检查通过。
- 整体 Go 1.26.1 编译、实际 Chromium、Electron 和 Flutter 构建仍未验证。
- 后台巡检间隔约 10 秒，撤销和并发写入之间**没有跨进程原子保证**；进程可能在下次巡检前继续运行。不可将它描述为实时强隔离。
- 终端缓冲输出不是可信执行证明；Git Worktree 已有的受控测试执行与审批门禁仍为独立的验证链路。
