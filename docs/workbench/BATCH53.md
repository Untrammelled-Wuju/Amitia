# Workbench 第 53 轮：多端视图生命周期与任务检查点对账

## 目标与变更

以第 52 轮累计完整源码为基线，本轮聚焦多端一致性剩余问题，不增加新的工作台执行系统。

1. 修复 Web 任务标签在初始化时误进入 Workspace/Git 加载流程的问题。通过独立的资源视图路由判定，在本机文件/Git/Diff 视图之外不自动请求工作目录；远端设备资源不向本机误路由。
2. 修复 Web 资源标签被 KeepAlive 缓存后，停用时旧异步文件/Git 响应可能继续写入，以及重新激活后未刷新实际资源的问题。通过生命周期代次废弃待完成读取，在重新激活后重查底层资源。
3. Web 任务的展开检查点按持久化任务更新时间绑定，任务产生新版本时重新读取；如果任务已从当前列表移除，关闭其检查点面板。过期、迟到的旧读取结果不得覆盖新版本。
4. Flutter 的展开检查点视图使用对话 ID、任务 ID 和更新时间作为缓存身份，使任务有新检查点时建立新视图并重新取证；关闭或切换时原请求仍由原生命周期控制。
5. 增加两套基于原始 Vue `<script setup>` 运行的隔离测试，覆盖标签类型请求路由、KeepAlive 重新激活和检查点迟到响应。加入现有 Workbench 研发门禁。
