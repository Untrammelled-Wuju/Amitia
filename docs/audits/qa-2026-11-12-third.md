- `AmitiaData/node/bin/node scripts/test/qa-electron-privacy-consent.mjs <隔离 Electron 日志> <隔离数据目录>`。真实 Electron 与 Core，三轮后台窗口回归通过。
- `python3 scripts/test/qa-pet-reinstall.py <隔离数据目录> <隔离 Electron 日志> <测试 petx> <petId>`。真实 Electron、Core、插件包、SQLite 和文件系统，连续两轮安装、启用、卸载与重装。双击确认的请求次数由 Core 访问日志核实。测试先断言页面自行更新，再刷新断言。
- 同一脚本加 `--fail-uninstall-refresh` 再跑两轮。通过 Chromium 调试协议在浏览器端断开一次真实安装列表 GET。页面保留安装卡片并显示 `ERR_NETWORK`，随后的真实请求成功后错误清除，卡片自行到达终态。两组共四轮，Core 各收到四次安装和卸载请求。完成后观察 7 秒，安装列表没有继续查询。证据为 `pet-network-e2e.log` 与 `pet-http-counts.log`。
- `python3 scripts/test/qa-pet-completed-uninstall.py <隔离数据目录> <恢复前 SQLite 备份> <操作 ID>`。真实 HTTP、SQLite、文件系统与进程重启。检查关联目录迁移、原操作不变、既有其他安装不变，`quick_check` 返回 `ok`。
- `go test -race ./internal/desktoppet/installation/recovery -run '^TestCompletedUninstallRecovery$' -count=10`。真实 SQLite 和文件系统，双恢复扫描、异空间、异设备、旧修订、仍在使用、启用状态和活动绑定均有断言。缺失目录保留原始文件系统错误，恢复目录后可重试成功。新回归在修复前因未收尾失败。
- `go test ./cmd/server ./internal/desktoppet/installation/...`、前端类型检查及 Vitest 1,115 项通过。最终隔离项目完成重启，聊天历史能重新读取。Core `/api/health` 返回 HTTP 200 且 `ready=true`，Qdrant 和 SurrealDB 进程存在。`/readyz` 为 HTTP 200，6 个组件就绪，唯一降级是可选浏览器组件缺少兼容 Chromium。
