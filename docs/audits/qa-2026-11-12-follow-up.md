# Amitia 深度 QA 续测 · 2026-11-12

本轮继续使用上一轮保留的 macOS arm64 隔离现场。Electron 主进程和 preload 从当前源码编译，Core 从 Go 源码重新构建。真实界面、数据库和进程测试都使用隔离数据。聊天推理继续使用环回协议替身。证据目录为 `artifacts/qa-20261112-next`。

| 场景 | 修复前证据与根因 | 修复与验证 |
| --- | --- | --- |
| 桌宠插件卸载未清理关联安装（P1） | 真实 API 返回插件已移除，关联桌宠仍为 `enabled`、`isActive=1`。统一包卸载没有调用现有归属清理器。 | 在不可回滚的收尾阶段写入恢复标记，按操作所属空间调用现有桌宠清理。回归注入原始错误，卸载进入待恢复，恢复后完成。独立桌宠、其他插件及其他空间使用单独归属断言。 |
| 桌宠卸载 ACK 跳过存储收尾（P1） | 接入清理后，新现场已撤销启用，但数据库同时出现“操作完成”和“安装卸载中”。通用 ACK 投影过早完成卸载操作，恢复执行器不再扫描。 | 成功 ACK 保留卸载操作供现有恢复执行器完成存储和绑定收尾。真实 SQLite 回归先失败后通过。真实包卸载后，关联安装进入 `uninstalled`，生成一条回收站记录。 |
| 重装桌宠插件沿用已解除的资源登记（P1） | 重装及启用都返回成功，SQLite 没有新安装 ID。桌宠贡献登记仍带旧句柄，启用只改状态。 | 重新启用已解除的贡献时重新挂载，安装桥跳过已卸载的历史记录，保留底层挂载错误。禁用后启用、卸载后重装的登记回归均在竞态检测下重复 3 次。 |
| 已卸载记录占用桌宠重装唯一键（P1） | 资源重新挂载后，SQLite 拒绝为同一个包创建新安装记录。空间、设备、桌宠唯一索引包含已卸载行，发布版本也受到跨设备的全局唯一约束。 | 当前版本按空间、设备和桌宠限制未卸载记录。已初始化数据库事务内更新索引，保留安装、操作和回收站数据。干净库和现有库的回归修改前失败、修改后通过。真实界面用同包完成两轮安装、启用、卸载，验证两个新安装 ID、两个已完成操作和各自回收站记录。 |
| Core 意外退出后 Electron 无法自行恢复（P2） | 两次隔离进程故障中，数据库子进程随 Core 退出。Electron 保持运行，Core 端点未恢复。现有退出处理只撤销端点。 | Electron 在当前部署下只尝试一次自动恢复，复用部署协调流程。主动停止与关机中的退出不触发。恢复失败时运行状态与原生提示保留信号或启动错误。真实强退后 Core 更换进程及端口，原 Electron 窗口读取到之前的聊天。再强退一次时没有继续重启，preload 返回的失败状态保留 `SIGKILL`。 |
| 聊天搜索（回归脚本） | 使用世界书作用域探查设备聊天会得到空结果。原脚本还要求同一用户关键词至少命中两条，模型替身回复使用不同文本。 | 用真实会话作用域分别搜索相同会话的用户文本与助手回复，逐条匹配角色与内容，并继续核对重复提交不增加记录。修正后的真实 HTTP、SQLite 和模型替身回归 18/18，0 个 HTTP 5xx。 |

最终验证包含受影响 Go 包定向测试、桌面类型检查、桌面 Vitest 466 项通过和 1 项既有跳过。Core 启动时在桌宠归属清理器注册后才执行扩展包恢复。最终源码完整重启后，Electron 读回聊天，Qdrant 和 SurrealDB 进程存在，Core 报告 6 个组件就绪，SQLite `quick_check` 通过，3 条测试桌宠卸载记录均可读取。可选浏览器因缺兼容 Chromium 可执行文件降级。

复跑入口为 `scripts/test/qa-pet-reinstall.py`、`scripts/test/qa-electron-core-recovery.py` 和 `scripts/test/qa-mesh-chat-e2e.py`。对应证据为 `pet-two-cycle-final.log`、`core-fault-final.log`、`core-fault-runtime-error.log` 和 `chat-regression.log`。

首轮的隔离现场仍保留一条曾被旧 ACK 路径错误标记为完成的卸载记录，仍显示为卸载中。此次修复验证了新卸载的收尾流程。首次隐私同意后的界面滞留仍待定位。未验证平台和外部依赖范围沿用首轮报告。
