# Owned 聊天原生多 Agent 整合修复

本报告对应 `owned-chat-multi-agent-gap-20261015.md` 的问题和已确认修复方案。本轮只修改源码、执行定向自动化验证并重新启动开发服务，不构建 Android APK，不提交或推送 Git。

## 整合结果

- 原生委派、状态和等待工具提取到 `backend/cmd/server/native_multi_agent_runtime.go`。旧适配器和 Owned 聊天共用同一实现，没有复制第二套协调器。
- Owned 父回合使用统一 Interaction 注册入口和持久账本。父请求身份包含 Core、所有者、发起设备、角色、会话和原请求编号，避免不同所有者的同名请求串台。
- 父回合结算延后至 Owned Engine 完成所有者提交后。普通回复成功、未提交回复、后台任务进行中、子任务完成待审核和取消分别处理；子任务成功不能掩盖父回复失败。
- Worker 在独立后台上下文中通过 Owned Engine 执行，使用稳定子任务编号、独立会话和隔离工作树。内部 Worker 禁止递归委派。
- 派发意图先保存，重复相同委派返回原协调任务，变更参数拒绝。已进入处理但运行时不再持有的 Worker 显式等待核对，不自动重跑未知副作用。
- 后台协调和恢复重新取得真实执行授权，核验 Core、所有者、角色版本、提供者、模式和权限修订。撤权停止真实 Worker 并持久化取消原因，不沿用新权限重试旧任务。
- 父请求断线与明确取消分开处理。后台任务可在 HTTP 结束后继续；明确取消先保存取消意图，再停止子任务并保存终态。停止或持久化临时失败可重试。
- 父 continuity 租约分区保留在父回合中；可信任务派生独立普通 Owned 范围，仅清除 continuity 分区，完整保留其他授权围栏，由后台入口重新核验。
- 云 Core 通过现有可信 DeviceMesh RPC 在目标设备分配工作树和读取审核摘要，复用已有工作树、检查点与合并审计。离线、撤权和错误归属不回退到云 Core 本地路径，不自动批准或合并。
- 两端现有 Owned 流接收真实任务事件，校验执行范围、任务状态与实际会话后刷新原工作台。没有新增重复任务页面，后台轮询保留。
- 模型调用原生任务工具后，未完成或待审核状态由确定性结果约束，避免模型把子任务成功表述为代码已验证合并。普通聊天保留流式输出。

## 联测发现的必要前置修复

真实项目接口联测发现，项目创建在比较权限范围前漏算记忆范围，与查询和聊天使用的范围不一致，合法创建返回冲突。已调用相同的 `ResolveMemoryScope` 补齐计算，没有放宽比较条件。
