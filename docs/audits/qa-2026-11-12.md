# Amitia 全项目深度 QA · 2026-11-12

测试基线为 `develop` 上的 `fc68315d` 加测试开始时已有的 6 个前端和移动端工作区变更。本轮使用 macOS arm64、项目自带 Node 26.12.1、Electron 43、Go 和 Flutter。业务写入、归档篡改、并发请求及进程故障注入均发生在独立 QA 数据目录。Core 从当前源码编译，Electron 主进程与 preload 从隔离源码副本编译，渲染端使用当前前端源码和项目既有的 5178 端口。Core、Qdrant、SurrealDB 使用项目的动态端口机制。测试目录仅使用测试角色、测试归档、桌宠夹具和环回模型服务。

## 功能入口地图

复跑 `python3 scripts/test/qa-source-map.py artifacts/qa-20261112` 可生成源码地图与逐入口覆盖表。提取了 1,480 条候选入口，其中 Web/Electron 路由 101、Electron IPC 42、Core 1,066、Flutter 页面与路由 220、管理端 API 40、管理端 Web 路由 11。另有 12 个插件清单、67 个表名声明来源、2 个 SQL 源文件。候选入口包含分组、重定向及条件注册。真实注册路由另从隔离 Core 启动日志抽取，保存在 `read-routes.tsv`。

主链路为 Vue 或 Flutter → 权限与部署模式 → Core 或 Device Agent → 归属业务服务 → SQLite、扩展内核数据库或文件。桌面另经 preload 和 IPC 访问本机能力。向量与图数据分别依赖 Qdrant、SurrealDB。插件中心、游戏、MCP、任务和工作流通过各自 API 调度插件宿主和任务宿主。管理发布服务有独立的 Web、API 和数据库。

## 已修复缺陷

| 编号 | 级别 | 复现、原因与影响 | 修复与回归 |
| --- | --- | --- | --- |
| QA-01 | P1 | 在空模型库发送 `POST /api/model/configs {}`，HTTP 和业务码均为 200，出现启用的空配置。外部模型跳过必需字段检查，首次配置还会自动激活。 | `backend/internal/chat/configuration_context.go`、`model_local_runtime.go`、`model_service.go` 统一创建、编辑、激活的服务端校验。外部模型检查地址与模型标识，保留无认证环回服务和无显示名的引导提交。嵌入式仍走已有资源校验。真实 Core 7 次无效创建均被拒绝，原记录不变。 |
| QA-02 | P2 | 在连接测试中输入 `http://%`，连续 3 次返回空体 HTTP 500。请求构造错误被丢弃，随后的请求头操作触发 nil 解引用。 | `backend/internal/chat/handler.go` 保留原请求构造错误并按现有连接测试契约返回失败。原路径连续 3 次返回完整 `invalid URL escape`，且连接状态为失败。 |
| QA-03 | P1 | 引导页选 Ollama，用只在 `/api/tags` 提供标签列表的替身，实际请求 `/models` 并出现 404。默认地址还附带 OpenAI 的 `/v1`。 | `StageModelConfig.vue` 和 `useImmersiveOnboarding.ts` 使用 Ollama 根地址，按当前提供商检测并在页面保留错误详情。真实 Electron 同样操作识别出 1 个模型，错误地址仍可查看原始解析错误。 |
| QA-04 | P2 | Ollama 检测成功后切换到在线模型，界面仍显示旧模型列表及成功状态。检测结果没有绑定本次地址与提供商。 | `useImmersiveOnboarding.ts` 在配置或 Core 权限上下文改变时清除旧检测状态，并以检测代次拒绝晚到响应。真实页面切换后立即显示等待检测，延迟响应组件回归通过。 |
| QA-05 | P1 | 隔离 Device Agent 同一目录 8 路注册，返回 3 个不同挂载 ID。查重和插入分属不同临界区，导致重复落库。 | `backend/internal/workspace/service.go` 和 `registry.go` 串行化持久挂载注册与删除。新挂载先落库再发布到注册表，保留错误链。SQLite 并发回归修复前重复落库，修复后竞态检测连续 20 轮通过。真实 Device Agent 8 路同 ID，强退、重启读回、删除和源文件检查通过。 |
| QA-06 | P1 | 桌面主动任务页填写完整提醒后创建失败，原始错误为“标题、所属角色或内容无效”。表单没有收集或提交后端强制要求的角色 ID。 | `front/src/views/tasks/ActiveTasksView.vue` 加载当前统筹中心角色，唯一时预选，多角色时显式选择，提交前复查 Core 和角色，保留原始错误。真实页面创建、暂停、刷新、恢复、取消后列表清空。两项组件回归修改前均失败，修改后通过。 |
| QA-07 | P1 | 最终 Core 回归中，同一子任务被两个执行器执行。单独重复 20 次有 3 次失败。后到执行器读取已是 `processing` 的记录后，仍调用同状态 CAS，而状态机允许幂等同状态更新。 | `backend/cmd/server/owned_multi_agent_worker.go` 将领取限定为对 `received` 版本执行 CAS。新增共享 SQLite 回归，强制后到执行器在首个进入引擎后执行，修复前稳定失败。原并发用例及新增用例各在竞态检测下重复 20 次通过。引擎为替身。 |

## 尚未关闭的问题

- P1，桌宠插件卸载两次均返回成功且插件列表移除。真实界面和带本机设备身份的安装 API 仍读到该插件生成的桌宠记录为 `enabled`、`isActive=1`，运行时同步为 `failed`。待进一步验证统一卸载路径是否完整调度了既有资产归属清理，当前保留隔离现场。
- P2，Core 被强制结束后，数据库子进程如期退出，但本次桌面外壳没有自行恢复，通知 SSE 重连记录了空基地址和 `Desktop runtime endpoint is unavailable`。完整重启恢复。桌面自动恢复要求及退出等待仍需独立复现和定位。
- P2，首次同意隐私说明后，地址已切换到聊天页，旧引导 DOM 和弹层在一次测试中仍留在界面，刷新后聊天正常。桌宠卸载时也观察到一次确认框内容停留，刷新后列表和服务状态正确。两条现象的根因尚未确认。
- 待判定，现有聊天脚本对固定用户关键词要求至少 2 条命中，替身返回不同文本时只得到 1 条用户消息。另一次搜索替身回复文本未命中，但页面刷新能读回回复。保留原断言和失败记录，搜索索引、范围与脚本预期需进一步核对。
- P3，首次 Device Agent 生命周期脚本在就绪接口超时，重跑进入功能验证。初次桌宠旧夹具因 preload 缺少 `onAutoLaunchChanged` 失败，桌宠正式结果来自真实 preload。两项初次结果均保留。
- 可选浏览器依赖在隔离 Core 中降级。Android ADB 无连接设备。当前环境没有真实外部模型和渠道账号参与本轮业务测试。详细缺口见覆盖矩阵。

本轮源码和回归脚本保存在项目中。既有未提交的 6 个文件保留，未提交或推送 Git。临时 QA 进程在验证后已停止，隔离数据和运行证据保存在 `artifacts/qa-20261112`。
