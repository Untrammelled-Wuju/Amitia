# Workbench Owned 任务接入修复

日期：2026-10-15。

对应审计：`docs/audits/workbench-owned-contract-gap-20261015.md`。

## 修复内容

手机端、电脑端的任务列表与检查点查询统一携带真实会话 ID、会话原始所有者、角色和预期执行 Core。UI 的 `meshconv1` 引用只用于页面标识，不再直接用于后台账本查询。

后端继续使用同一份 InteractionTracker、多 Agent 协调器和持久化任务投影，没有新增任务数据库、调度系统或第二套任务页面。

### 后端

- `business.WithConversationRead` 复用现有协调作用域、能力授权、角色读取、Owned 会话路由和 ResourcePort，解析当前真实会话 ID，包括 `continuation/…` 续接 ID。
- 查询前验证会话确实属于当前授权所有者和角色，查询结束后再次验证权限、角色版本及会话资源版本。权限撤销或状态变化后不返回已失效结果。
- 本机 UI、已认证设备统一经过同一会话授权流程。移除任务接口仅接受 LocalUI 的旧判断，未认证或不支持的主体仍然拒绝。
- 任务创建时将执行 Core、资源所有者写入现有多 Agent 检查点；随运行状态更新及恢复保留，并纳入描述符指纹校验。来源使用服务端 Owned 执行上下文。
- 任务查询同时核对空间、角色、真实会话 ID、任务保存的 Core/所有者，以及所属回合的持久化凭证。不同所有者即使会话 ID 和请求编号相同也不能互读。
- SQLite 的最近任务查询先按角色过滤，再应用上限；保持既有采样、列表上限和截断提示。
- 统一返回查询上下文，供两端核验响应来自预期会话、角色和 Core。无效上下文返回 400，无权访问返回 403，会话或任务不存在返回 404，归属变化返回 409，依赖不可用返回 503。

### 两端

- 电脑端 `workbench-task-api.ts`、手机端 `workbench_task_service.dart` 集中处理查询契约、归属验证和错误映射。
- 角色从当前聊天入口传入工作台、任务列表和检查点组件。
- 任务列表与检查点共用业务 Core 路由，未将云端任务硬编码改为本机查询。
- Core、权限版本或响应归属变化时丢弃响应；切换角色、会话、后端连接时清除旧任务显示，阻止旧请求结果覆盖当前页面。
- 电脑端取消过期查询；手机端使用组件请求代次和服务生命周期校验丢弃失效请求结果。
- 查询失败与确实没有任务分别显示，不使用空列表掩盖权限或连接错误。

## 数据处理

未删除现有业务数据，未修改数据库表结构，因此没有新增数据库迁移。

新增归属字段存放在已有检查点 JSON 中。缺少可信归属凭证的历史任务记录不会猜测所有者或跨设备展示；没有新增历史数据推断、回填或兼容分支。持久化回合凭证用于核验归属，不依赖用户消息仍然存在。
