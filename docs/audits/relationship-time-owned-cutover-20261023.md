# 关系时间统一链路修复与验证

日期：2026-10-23。范围：关系时间、久别重逢、电脑端与手机端接入。未修改管理端，未调整版本或项目端口，未推送 Git。

## 方案

采用数据所有者执行、持久化完成凭据、可重试幂等消费和权限版本校验。复用现有 Owned 聊天、Owner 后处理端口、完成 checkpoint 与记忆恢复 Worker；不新增独立执行器或第二套关系时间算法。参考 Transactional Outbox 与 Idempotent Consumer 的可靠提交原则，跨数据库通过现有持久化完成记录恢复，不能把它表述为跨数据库原子事务。

参考：https://microservices.io/patterns/data/transactional-outbox.html ，https://microservices.io/patterns/communication-style/idempotent-consumer.html 。

## 原有能力迁入

继续使用 temporal 中的节奏估计、全局回归与角色重连分类、主动联系识别、占用租约、连续性、重新适应回合、重逢策略、表达限制、事件历史与效果账本。

聊天快照由真实 Owner 准备关系时间及策略。成功回复通过已有 Owner 后处理提交，原始 requestId 定位回执，重试和恢复不会重复计数。主动联系记录助手联系时间，不伪造用户成功互动；内部工作不登记为用户互动。失败、取消和抑制回复通过同一 Owner 通道释放占用，成功回复的持久化完成记录防止误释放。

关系时间渲染进入 Owned 模型上下文。保留任务优先、旧话题确认、共同记忆预算、关系年龄许可与临时表达调整。修复句数为 0 被忽略以及 expressive 突破用户句数上限的问题。

## 归属与客户端

关系状态使用空间与 Owner 的确定性命名空间；角色设置使用 Owner 与角色的确定性键。既有表和仓储继续复用。旧本机数据事务迁入本机 Owner，不复制给 Core。重复启动不会重复迁移。

新增现有 business 路由下的 relationship-time 管理入口，经过统一角色、能力、归属和权限校验。远程调用复用 coordination.data 设备通道。本地、云端非统筹与 Core 统筹使用相同逻辑。保存必须使用加载设置时的原始 executionScope 与 updatedAt；过期权限、模式切换与并发旧版本写入被拒绝。

电脑与手机保留现有页面和服务入口，设置、状态、历史及历史事件详情均使用 Owner 接口。设置权限绑定在具体设置对象上，刷新其他 Owner 的状态不会改变原表单写入目标。
