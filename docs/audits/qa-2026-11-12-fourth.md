# Amitia 深度 QA 第四批 · 2026-11-12

范围包含桌宠卸载列表的边界、MCP 本机进程生命周期、两种传输注册表和 Electron MCP 配置页。环境为隔离 macOS arm64、项目 Node、Electron、当前源码构建的 Core、真实 SQLite。测试数据沿用第三批。前端端口 5178，Core 使用运行时动态端口。证据位于 `artifacts/qa-20261112-fourth`。全项目入口与历史覆盖见 [首轮矩阵](qa-2026-11-12.md) 和 [第三批报告](qa-2026-11-12-third.md)。

| 场景 | 方法与结果 |
| --- | --- |
| 桌宠离开页面时取消请求 | 将一条已完成的隔离 QA 记录临时改为持续等待，借助 Chromium 调试协议暂停一次真实列表 GET，随后切到聊天页。观察到该请求的 `Network.loadingFailed.canceled=true`，离开后 7 秒无列表查询。 |
| 桌宠连续等待到上限 | 重返桌宠列表并等待完整 60 秒。页面保持“卸载中”，最后一次真实 GET 在 59,883 毫秒发出，随后观察至约 73 秒无新增查询。夹具在 `finally` 恢复，SQLite `quick_check` 为 `ok`。 |
| P2 MCP 慢握手阻塞无关服务 | 一个 stdio 子进程延迟握手 4.2 秒，无关的健康进程断开在修复前连续三次耗时约 4.19 秒。stdio 和 HTTP 注册表在等待创建及握手时持有全局锁。按服务 ID 协调现有启停后，Core 真实进程回归三次断开分别耗时 5、7、4 毫秒，慢服务仍在握手。对同一慢服务并发连接只产生一个子进程。两项循环内检查进程退出及配置清理。 |
| MCP HTTP 并发与取消 | 本机实际 HTTP 请求经过完整注册表和传输。延迟握手期间独立关闭另一个服务，同一服务的重复启动共享连接。等待超时保留 `context.DeadlineExceeded`。关闭注册表取消在途握手，HTTP 服务也收到取消，未登记失效连接。两项测试各在 Go 竞态检测下重复 10 次。 |
| MCP 页面与无效命令 | 通过扩展中心进入 MCP 页面，完成配置保存、连接、查看真实发现的 `echo` 工具、离开再进入、断开。另一个不存在的命令通过真实 API 返回 HTTP 400，保留完整命令解析错误，服务详情记录同一错误。 |
| P2 MCP 子进程强退后假就绪 | 隔离 stdio PID 收到 `SIGKILL`，接口仍返回 `ready`，6 秒内没有新进程。新增回归预期新进程完成握手和工具恢复，修复前失败。 |
| P2 MCP 添加成功后弹层滞留 | 真实页面拒绝缺少命令的配置。填写后显示“服务已添加”，真实 API 已读到配置，后台窗口的表单和旧校验仍滞留。另一次取消后也观察到弹层滞留。 |

强退重连和表单滞留已提交修复方案，仍待确认。回归用例已保存，当前基线预期失败。
