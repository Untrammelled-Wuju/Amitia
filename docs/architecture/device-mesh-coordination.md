# 多设备配对与 Core 统筹

## 已确认方案

设备身份、业务 Core、授权域、角色来源及数据所属位置分别管理。扫码设备使用展示设备的业务服务，任意设备平台遵循同一协议。配对关系不直接授予管理员或其他设备执行权限。

配对采用短时一次性 Offer、持久设备身份、设备独立凭证和受限局域网入口。完整安全配对还需提供者确认、TLS 身份绑定和设备密钥证明。重复、自扫和并发添加由服务端拦截。

使用远端服务时，AI 对话、摘要和记忆计算始终由当前 Core 负责。每台设备独立控制统筹模式：关闭时使用设备角色，新聊天、记忆、衍生数据及持续事项归设备；开启时使用 Core 角色，新数据归 Core。历史数据不迁移，仍按来源和权限查询。

管理员必须处于有效配对及已开启统筹状态，并由当前 Core 明确授予。管理员设备使用与 Core Web 相同的服务端数据源。模式关闭、解绑、撤销和 Core 改变均使管理员资格失效，重新开启不自动恢复。

A 使用 B，B 转接 C 时，A 申请 C 独立授权并直接连接 C。禁止继承 B 的凭证和管理员权限，禁止循环连接。切换中断当前生成，保留已完成动作，屏蔽旧提供者迟到输出；显示提供者变更提示，用户主动继续。只传必要上下文，不迁移 B 云端数据库。

跨设备保存采用事务 Outbox、请求去重及提交确认。设备离线时显示待保存，不将投递缓冲变成永久云端数据。任务采用单一有效调度者、租约、版本和检查点，不重放已完成或结果未确认的动作。

参考规范：[设备授权 RFC 8628](https://www.rfc-editor.org/rfc/rfc8628.html)、[OAuth 安全 RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)、[DPoP RFC 9449](https://www.rfc-editor.org/rfc/rfc9449.html)、[OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)、[事务 Outbox](https://learn.microsoft.com/en-sg/azure/architecture/databases/guide/transactional-outbox-cosmos)。上述资料提供基础机制，统筹模式与历史数据归属是 Amitia 的产品规则。

## 当前完成范围

凭证交换客户端使用后端实际公共接口。配对领取将设备登记、票据签发及 Offer 消费放进同一事务，失败回滚。服务端拒绝自扫、已添加设备及同设备并发领取，并提供稳定错误码和中文提示。撤销事务同时处理设备信任、访问凭证、未使用票据及该设备生成的 Offer。本地认证接入持久 Device Mesh 身份，使本地 Core 能生成 Offer。

当前已增加真实二维码 PNG、Web 摄像头及图片识别、手机原生相机扫码，保留手动输入。扫码仍通过既有 Core 地址及配对领取流程执行，尚未完成自动开启局域网入口和切换 Core 地址，因此不能据此宣称任意设备互扫已完成。

新增每台设备独立的统筹策略、模式与权限版本、显式管理员授予接口。普通设备不再因配对而自动拥有 Core 管理员权限，模型配置页面和服务端管理接口共同校验权限。聊天通过只读可用服务接口获取信息，普通设备提交的模型和推理配置覆盖参数由 Core 忽略。关闭统筹、撤销及更换 Core 均使已授予的管理员失效。

新增不可变执行范围、状态变化取消、提交校验、设备数据事务存储和持久投递队列。跨设备执行按目标设备的模式决定数据与角色归属，同时校验调用方和目标方的版本与有效配对。队列按所有者隔离请求编号，设备提交支持内容哈希去重、版本检查和事务确认，确认后删除 Core 中的正文缓冲；失败投递按退避间隔重试。记忆删除使关联向量和图谱记录失效，已删除来源拒绝迟到索引。

新增业务计算端口已接通 Core 模型、角色来源、所有者提交、记忆提取和持续事项调度。当前源码支持网页及手机对话流、当前和原设备消息分别分页、编辑版本校验、摘要与记忆作业恢复。记忆更新先向持有方补查上下文窗口以外的实际版本，删除来源拒绝再次生成。持续事项正文与租约只保存到所有者，Core 仅保留位置及调度版本；暂停中断生成，过期执行标记结果未知，人工确认后仍保持暂停且不重放本次等待。事件解析按等待条件精确匹配，通过所有者提交后再由 Core 调度。

会话列表已分别读取当前所有者和原设备的全部分页，并限制重复游标、旧权限游标和迟到页面。持续事项采用四项并发上限；所有者在同一提交事务内校验执行租约，续租不会使记忆计划失效，执行完成后仅允许根据已确认保存的回复补写原记忆计划。绑定后，旧对话及向量计算入口也受 Core 权限边界约束，解除绑定失败不会恢复本机计算。

记忆查询向量由 Core 计算并传递到持有方，向量记录携带实际生成配置的指纹。持有方能够检索近期窗口以外的来源记忆，并过滤其他所有者、其他角色、已删除、禁止上下文使用、过期、不同模型或维度不一致的记录。所有者维护 Qdrant、SurrealDB 投影作业，仅保存索引位置和版本元数据；来源修改及删除触发重建和清理，失败退避，旧版本不能标记成功。Qdrant 检索结果逐条核对 SQLite 来源版本，索引不完整或暂不可用时从所有者原始向量检索。真实服务测试已覆盖写入、删除、角色隔离和旧索引回退，新库与旧库迁移测试均通过。

网页聊天、独立记忆管理页及手机主要记忆入口已展示原始记忆、六层衍生数据及摘要，支持按数据归属分页、停用和删除原始记忆。管理查询能够查看停用数据，推理查询仍排除停用数据。修改提交携带页面看到的完整执行范围，Core、角色、所有者、模式或权限版本变化时拒绝旧页面修改。解绑意图持久化，进程中断后先完成本地权限重置才恢复本机计算。远端归属写入持有同机共享的凭证锁，解绑及凭证替换与所有者提交串行；调度器保留提前到达的取消记录，并拒绝旧连接已解析的执行器。持续事项列表增加独立分页，网页与手机读取完整列表并拒绝重复游标和混入其他执行范围。

统筹设备可按原设备历史角色目录读取旧归属记忆及旧数据库中的原始记忆、画像与情节记录。两个存储的游标独立，先读完的来源不会重新加载；历史游标绑定完整 Core 执行范围。该目录只标识历史数据位置，不使用设备角色设定执行新对话。历史查看入口保留在原设备，不迁移、不复制到 Core 数据库，当前界面提示在原设备管理历史记录。

设备能力解析已覆盖浏览器、游戏宿主、工作区及声明为设备端的插件模块，强制使用本次授权目标设备，目标不可用时拒绝调用。声明为云端的模块使用 Core；解析器返回其他设备或空间时拒绝执行。本地独立游戏宿主调用保持原路径。手机与网页消息保留来源所有者、完整权限快照及读取时版本，编辑和删除不会使用后来刷新出的版本覆盖旧页面。旧数据库消息目前仍通过原设备管理，不能借同名记录修改当前所有者的数据。

设备与 Core 的索引管理入口展示当前角色的向量、图谱处理数量、待更新数量和重试数量，手动重建提交携带页面的完整权限快照。重建只重置对应所有者、角色及资源类型的索引作业，不修改原始记忆。所有者确认排队后再显示等待处理，不能将排队当作索引完成。已删除设备角色的旧记忆保留目录位置，可由 Core 显式指定历史角色在新对话中读取，历史角色设定不参与 Core 对话。

设备在断线取消执行前先退出可调用状态，能力解析期间会话变化时再次拦截。读写数据都持有当前配对凭据校验，解绑或待切换期间旧 Core 不能读取原设备历史。持续事项与已保存回复的完整权限范围在所有者提交事务内再次核对，替换租约、过期、未知结果、暂停、删除及其他空间的数据均拒绝迟到记忆写入。

设备列表已提供通过 Core 调用其他设备及按调用方、目标、能力配置授权的入口。零角色拒绝、单角色默认、多角色选择，提交时携带选择页面的完整权限范围；角色、模式、权限或提供者变化时，在保存输入及计算之前拒绝旧范围。网页和手机调用页面显示当前 Core、目标设备和新数据所有者，提供者变化时中断并提示前后提供者，只有所有者确认保存后才显示已保存。

图片附件增加随消息保存的通道，单张上限 1 MiB、单条最多两张，支持 PNG、JPEG 与 GIF。客户端计算 SHA-256，Core 校验内容类型、尺寸和完整性，输入及图片获得所有者确认后再计算回复，关闭统筹时不另行上传到 Core 附件库。同一请求改变附件被拒绝，重新读取可显示所有者保存的图片。消息分页增加字节上限及连续游标；设备传输帧上限为 8 MiB，业务载荷仍保持 4 MiB 的独立上限。

Core 对发出的设备数据请求持久记录请求编号、调用方、目标和连接代次。统筹、管理员、能力授权、解绑及 Core 改变之前，等待受影响持有方确认旧权限屏障，持有方在共享配对锁内持久关闭旧权限版本，迟到请求不能再读取或写入。存在未确认远端结果且持有方离线时，权限变更保持失败，不将其报告为成功。重连按旧会话请求编号建立持久取消记录，得到持有方确认后清理 Core 未确认记录，保留统筹、角色、管理员状态及新连接请求，原数据提交可用新调用编号按所有者收件箱继续核对。屏障失败后部分持有方可能保持暂停，需恢复连接并重试变更；不得自动放开旧版本。已增加实际设备数据处理器、并发屏障和重启恢复的定向测试，仍需多实例端到端验收。

安全局域网入口、设备密钥证明及独立审批已进入源码。A→B→C 使用 A 自身身份在 C 配对；候选凭证与待审批状态受本机凭证保护，失败和重启保持暂停。切换确认校验通道、Core 业务就绪、角色来源、数据归属及配置版本，成功后直接使用 C，并清理候选状态。收到撤权后停止连接及任务；旧绑定版本不能重新恢复原服务。当前业务门禁 `BusinessCoordinationReady` 仍保持关闭，不得在下述剩余适配和端到端验收完成前打开。

设备工具调用已携带完整执行范围及独立授权请求编号，并接入上述持久屏障。源设备在共享配对锁内校验调用方、目标、所有者、授权域、权限关闭记录及请求取消记录，校验位于持久执行结果读取之前；缺少执行范围或持久执行端口时拒绝调用。工具执行记录的内容哈希包括角色和完整权限范围，同一动作更换范围拒绝复用结果或再次执行。Core 去重入口校验参数及范围指纹，重复调用等待响应提供者取消，未确认的设备归属执行记录在重启或过期后拒绝自动接管。对应定向测试及竞态检查通过，任务派发与工具结果数据归属仍需继续适配。

关闭统筹时的记忆管理已接入设备原有记忆、画像及情节库，与新归属资源分别分页；所有者、角色和权限变化使旧游标失效。网页及手机传递独立旧库游标，先读完的新存储不会重新开启。开启统筹时仍通过原设备历史来源读取这些记录，不将设备原库归类为 Core 新数据。旧库管理写入和完整时间线入口仍待适配。

关闭统筹的工具结果增加独立所有者资源，包含参数指纹、执行范围及完整结果。Core 去重结果只保存位置和 SHA-256；所有者确认失败时记为结果未确认，并使用有界 Outbox 等待保存。再次调用先读取所有者已确认结果，核对参数及范围，避免重复动作；版本冲突不进入投递队列。审计输入、输出及副作用保留哈希与状态，正文及详细错误不写入 Core 记录。已增加实际本机持有方确认、缓存正文隔离和审计正文隔离测试，跨设备掉线重连和审批记录仍待完整验收。

仍需完成的业务闭环：

- 手机与电脑四种组合的扫码端到端验收，浏览器设备在关闭统筹时的数据执行端口，以及不同平台的密钥和局域网恢复。
- 历史记忆跨角色的语义检索与引用、历史记录管理入口及投影管理端到端验收。
- 图片其他入口及完整端到端验收，语音、视频、主动消息、项目分组、历史编辑、归档搜索与导出等入口的归属适配。
- 原有持续事项访问和迁移之外的接续方式，内核任务、工作流及审批事件的可靠事件投递。
- 内部工具、插件、浏览器与任务的执行位置和所有者适配，跨设备调用端到端验收及完整审计。
- 远端写入与权限撤销的多实例及故障端到端验证、提供者完整就绪屏障的生产验证，以及服务重启后的健康验收。

当前实现仍不满足整套方案的完整开发验收条件。

真实 TLS 1.3 和 WebSocket 多实例测试已覆盖设备凭证与 Ed25519 请求签名、请求重放拒绝、设备消息仅存于设备、旧连接未确认调用的重连封锁、权限屏障 ACK、旧调用取消与新权限恢复读取。该测试发现并修正了首次握手错误要求已存在会话 ID，以及重连错误要求客户端预知服务端新连接代次的问题。初始 Hello 只校验基础信封、身份与正文哈希；建立连接后的消息仍要求服务端分配的会话和当前代次。

实时撤权关闭码和握手鉴权拒绝现已使设备进入撤权状态并停止重连。永久性的所有者、请求冲突、资源版本和角色拒绝通过稳定错误码传回 Core，保留可判断的错误类型；已确认未执行的拒绝可以清理远端未知调用记录，连接中断和执行结果不明仍保留记录，不能当作未执行或自动重试。

Windows 与 Android 四种发行端及加入端组合已通过签名配对、发行端批准、凭证交换、重复添加拦截和身份密钥复制拦截测试。该覆盖属于平台协议组合测试，并非四种真实设备相机扫码验收。

任务协议已增加完整执行范围和远端授权调用编号，设备任务在认领租约之前以及读取持久化执行结果之前执行同一套凭证、来源权限和角色校验。任务执行上下文保留设备数据归属，缺少校验端口或持久化执行账本时拒绝执行。异步任务队列的持久化授权恢复与所有者数据端口尚未接入，当前拒绝把受控调用送入会丢失执行范围的旧队列；此入口拦截不代表任务调度全量完成。

内核能力执行现在把完整设备授权范围写入既有 ScopeSnapshot。SQLite 在既有 JSON 列中使用带版本的快照文档，兼容旧数组格式，并保存授权域、数据所有者、角色版本和双方权限版本；设备授权快照创建后不能被覆盖或降级成普通快照。内存快照同样拒绝修改，并在读写时复制授权字节和范围列表。队列入队和调度入口读取持久快照，检查调用、扩展、模块及到期时间，拒绝授权丢失或被替换；Coordination 恢复接口重新注册原执行范围，模式或权限变化会取消恢复后的任务。任务所有者执行器尚未接入，生产入口继续拒绝受控任务，不能据此认为持续任务已完成。

权限变更在等待源设备关闭旧权限之前，先取消受影响的 Core 执行，释放源设备正在运行的角色及配对锁，然后等待源设备持久屏障确认；屏障失败仍不提交新权限。真实 TLS 多实例测试覆盖运行中原生动作收到取消、源设备屏障完成、旧权限失效和新连接恢复，竞态测试通过。

私有语音识别直接使用内存音频，使用 Core 当前配置的 OpenAI 或 Azure 服务，识别结果直接返回，不另存异步结果副本。PCM 分段不再写临时 WAV 文件，并限制缓冲、请求和响应大小；Core 切换或用户取消使上游 HTTP 请求立即取消。完整 PCM16 / 16 kHz WAV 校验及上游取消测试通过。

语音附件随消息保存，支持单段不超过 1 MiB 的 WAV 或 WebM。所有者确认原音频后才由 Core 识别，所有者再次确认转写后才生成回复与记忆；转写记录使用原消息 CAS 更新，不修改原始正文，避免首次转写被当作用户编辑而使旧摘要失效。后续检索与记忆使用转写文字，旧正文已编辑时不使用原转写覆盖正文。同一请求恢复已有结果，不重复识别或生成。网页录音、手机录音与手机音频选择已接入，历史音频从所有者记录恢复；手机以有界内存流播放，不另写音频缓存文件。转写 SSE 使用同一完整执行范围，迟到、重复和不完整转写拒绝。视频、其他音频格式、大附件分块以及只转文字和实时语音完整归属仍需继续适配。

生产配对状态统一使用内核设备注册表所在数据库，构造时拒绝分离的身份数据库。历史业务库中的配对票据、凭证和 Offer 在启动时一次性转入同机内核授权账本，原记录保留；重复启动不会重新导入已撤销状态，冲突时拒绝启动且事务回滚。此处理仅修正本机授权状态的存储位置，不涉及 B 到 C 的云端业务数据迁移。

## 验证要求

会话现在携带明确的原始所有者与原始会话编号。网页及手机使用包含所有者的页面标识，列表中的同名会话保持独立，只有持久记录声明相同来源关联时才合并为接续入口。统筹模式接续设备原会话时，Core 为当前角色创建独立的接续编号，原设备和 Core 中恰好同名的其他会话都不修改；查询 Core 自己的会话不会混入同名设备历史。旧调用缺少来源且两端会话同名时拒绝执行。

提供者切换后的旧 Core 会话只能通过显式传递的当前页面上下文建立新接续；新 Core 不读取旧 Core 存储，也不生成旧所有者数据副本。后续读取要求新 Core 已存在匹配来源关联的记录。此机制已通过后端真实存储及竞态测试，网页和手机也已接入查询、发送、保存确认与会话编辑的标识转换。旧页面编辑、删除及清空等待期间切换会话时，迟到确认不得改动新页面。归档、搜索、导出、项目与摘要其他入口仍需逐项接入。

所有者明确拒绝请求冲突或资源 CAS 写入时，Core 将待投递正文原子清除，只保留调用者、所有者、角色、会话、请求哈希及错误码等失败元数据。相同拒绝请求不能再次入队，离线及结果不明仍保留有界待确认记录。网页和手机在对应所有者会话中显示只读失败提示，不将失败状态展示为已保存；失败索引按所有者限制为 128 条，隔离其他调用者和角色。

TLS 权限切换联测发现并修正了并发发送先分配序号、后竞争发送锁导致取消消息被当作旧消息丢弃的问题。Core 与设备均在发送锁内分配通道序号，128 条双向并发发送竞态测试和连续三次真实 TLS 权限切换联测通过。语音完成结果必须与已收到的转写文字及所有者确认版本一致，缓存完成结果可直接校验；手机录音缓冲超过限制时清除并停止采集，拒绝发送截断音频。

基础测试覆盖凭证交换路由、自扫、重复、并发、失败回滚、过期、发行设备撤销及重新配对。后续验收需覆盖手机与电脑四种扫码组合、双方断线恢复、角色选择、模式独立和存储归属、管理员即时失效、上下文连续、记忆删除、跨设备调用、提供者循环及任务去重。

完整历史读取按所有者与消息编号保留来源，分别读完独立分页；总量限制为 4096 条及 32 MiB，重复游标、读取期间权限或消息版本变化均停止并提示重新加载。归档页面已使用该读取路径，旧加载不能覆盖后来选定的页面。摘要编辑保留页面读取时的所有者、真实资源编号、CAS 版本及权限快照，历史摘要只读；修改必须携带原页面的摘要视图凭证，同一会话重新读取或切换角色后，旧编辑窗口拒绝提交。手机明确导出时直接生成所选会话内容，正文不写入 Core 导出目录。网页归档支持从授权历史生成 JSON 下载，导出只包含对话正文、媒体及来源，不包含执行权限、令牌或其他运行状态。项目管理及其他历史入口仍需继续接入。

归档搜索在各数据所属端执行标题和消息正文筛选，只返回匹配会话元数据，不为了搜索读取全部消息。Core 和原设备保留各自独立的搜索分页；游标携带归一化搜索条件的 SHA-256，条件变化后旧游标拒绝使用。当前角色搜索隔离其他角色、其他所有者及已删除消息；统筹模式的原设备历史目录按已有历史授权范围搜索，消息关联仍要求属于同一所有者与该历史会话的角色。搜索内容限制为有效 UTF-8 且最多 256 字节，采用参数化 SQL。网页和手机使用服务端匹配结果，正文匹配的会话不会再次被客户端标题过滤丢弃。此实现是有界分页的子串搜索；大型聊天库的全文索引与 Unicode 大小写折叠仍需单独优化。

统筹模式下，设备执行日志仅持久保存动作编号、请求哈希、Core 身份和动作已执行状态，结果正文只随本次传输留在内存，不生成云端结果的永久设备副本。中断或重启后同编号请求返回结果不明，不能自动重新执行设备动作；已在 Core 确认的结果由 Core 自身的结果账本提供。关闭统筹模式时，设备仍可保留自己拥有的结果。新增重启、防重放和实际权限通道测试已通过。

任务进程宿主原有的固定等待后返回空成功已替换为真实 Node 标准输入输出协议执行。宿主校验进程 nonce、实例、任务归属与就绪会话，完成事件须等待实际进程退出后才能提交结果；提前退出、无确认结果、跨任务事件、取消后结果及未知执行端口拒绝报告成功。进程树取消与关闭已接入平台实现。插件入口从已安装目录解析，限制路径边界并校验源码 SHA-256；缺少完整性校验的定义仍拒绝执行。入口指纹传入实际 Task Host，读取量有界，校验后通过 Node 同步模块钩子加载同一份已校验字节；加载途中文件被替换也不能改变入口执行内容。CommonJS、ESM、入口替换竞态与真实 Task Host 子进程已验证。入口导入的其他文件及插件安装更新仍需进一步锁定。

跨设备任务输入不能覆盖已授权的任务编号。执行端须接收完整派发结构，保留根任务、尝试、租约、授权调用和目标插件指纹。Core 派发前查询目标设备实际安装的任务定义，按可移植定义指纹校验两端任务一致；本地安装代次与自动生成的声明哈希允许不同，入口、权限、输入输出约束和其他任务定义必须一致。目标设备的完整定义指纹及安装代次作为新的任务元数据保存于当前数据所有者，取得确认后才可派发；重派期间目标升级、离线或与原确认版本不一致均拒绝继续执行。设备动作去重指纹包含目标插件指纹，防止新版执行读取旧版结果。目标设备完整执行及所有者宿主 RPC 仍未闭环，生产业务门禁继续关闭。

本机暂停须先进入暂停中，等待宿主确认检查点及实际进程退出，再核对数据库检查点版本、哈希、任务定义和输入后提交已暂停。暂停失败进入待人工恢复状态，不能宣称暂停成功；停止尚未确认时保留暂停中。恢复检查旧进程已清理及检查点兼容性，然后增加执行代次并重新入队，不直接修改为运行中。恢复后的进度序号接续已保存序号，检查点客户端保留原游标并拒绝无效版本。任务进度、检查点和结果提交核对执行代次与状态，结果提交与 CAS 在同一事务中，旧回写和取消后的成功均被拒绝。异步远端执行保持授权上下文直至终态；授权或执行代次变化时先请求停止，停止未确认不能宣称结果完成。实际 Node 子进程、本机完整执行、暂停恢复、取消确认、SQLite 进度单调性及竞态测试已通过。任务所有者存储、受授权的宿主 API、远端暂停恢复与入口版本升级流程尚未闭环，设备任务业务门禁继续保持关闭。

摘要生成使用 Core 模型配置及当前授权角色，先读取全部授权消息，再取得所有者执行确认。生成后重新读取并比较消息与版本，最终按摘要 CAS 和当前消息依赖保存；只有所有者返回正确 ACK 才显示已保存。相同请求已完成时复用确认结果，已开始但结果未确认时不再次计算。关闭统筹时新摘要回写设备，开启时保存于 Core，原设备历史通过来源关联读取。网页和手机归档入口已接入；手机提供 JSON 与 Markdown 剪贴板导出。接口测试覆盖未授权、缺少页面版本、角色版本过期、重复请求、所有者归属及原消息不变。

任务宿主握手校验协议版本与持久执行代次，恢复进程使用实际代次。真实 Task Host 源码通过项目 Node 在内存中加载验证，未修改编译产物；该联测发现暂停确认后退出信号又触发失败结果的问题，宿主退出流程现在阻止再次发布结果。队列入队保存完整任务定义的 SHA-256 指纹，调度和恢复时比较当前定义；同一声明哈希下入口、权限或其他定义变化同样被拒绝。指纹通过追加内核迁移保存，既有迁移编号与校验和不变，CAS 和 Upsert 都不能替换任务原指纹。普通历史任务保留兼容读取，设备归属任务缺少指纹时拒绝执行。任务所有者存储和远端调度仍需继续闭环。

按阶段闭合这些验证后再放行端到端发布，不以主观百分比代替实测结果。

内核设备任务输入先提交到角色和数据所属的所有者，并核对所有者、请求编号及资源版本 ACK；未确认时不入队。队列仅保留输入哈希、原授权快照和定义指纹，执行时按完整原授权重新读取输入，读入内容只供本次进程或远端派发使用，不回写到队列正文。重试保留原调用、授权快照和定义指纹，并先取得新任务输入的所有者确认；已成功的设备任务禁止重试，结果未知且没有确认检查点时禁止恢复为从头执行。

检查点、进度和成功、失败、取消、超时及需人工处理的结果均有数据所有者端口，先确认写回再保存普通任务表的元数据。检查点和结果正文、进度内容及详细错误不会复制到普通任务表；读取时验证原授权、定义指纹、执行身份、所有者资源版本和内容摘要，再在内存中取得原始数据。外部、远程及监管进度回调对设备任务恢复原授权并接入相同写回流程，旧执行、失效授权、变更定义和错误 ACK 均拒绝提交。设备检查点删除在所有者确认删除流程完成前拒绝操作。真实设备数据端口隔离测试和任务模块竞态测试已通过。

远程任务派发携带完整原授权和持久化调用编号，终态收到所有者确认后才能确认该调用编号。断线、租约超时、取消请求和待处理记录消失均不等同于设备取消 ACK；只有执行、租约、会话和连接版本全部匹配的终态回执才可确认。授权确认失败保留待处理状态，已提交的相同终态可以再次确认，正文不同的重复结果拒绝。设备任务在服务重启或租约过期后进入结果未知状态，不因声明幂等而从头重跑，也不凭超时直接判失败；用户核对所有者结果或确认检查点后才可恢复。生产任务授权恢复器仍未启用，断线写回对账、宿主 API、远程暂停恢复和生产集成验收尚未闭环。

任务安装固定实际入口 SHA-256、安装代次和完整定义指纹，校验包目录边界及贡献身份。设备任务执行与数据提交复核定义指纹和安装代次，更新后的定义不能继续接受旧任务的数据；空闲进程每 200 毫秒复核授权，失效时停止进程树。任务专用存储按任务编号隔离，每个任务最多 64 个键、单值 64 KiB、值总量 256 KiB；存储正文只由数据所有者保存，读写依赖原任务输入确认，写入和删除采用资源 CAS 并核对所有者 ACK。Task Host 原始 TypeScript 源码通过实际 Node 子进程验证了存储读、写和删除 RPC，真实设备数据端口测试确认存储不会进入 Core 镜像或聊天上下文。

任务产物支持有界数据和文件保存及索引列表。每个任务最多 32 个产物、单个产物 1 MiB、累计内容 8 MiB；正文和索引在所有者处原子提交，输入版本依赖及两个资源版本 ACK 均须确认。超过 64 KiB 的 JSON 结果由所有者产物提供，普通任务表和终态引用只保存产物编号及摘要，读取结果时重新验证原授权、输入、产物版本和摘要，并只在内存中取得正文。Task Host 按 UTF-8 字节计算结果上限，无法序列化的输出报告失败。原始 TypeScript 子进程、真实设备数据端口及任务模块竞态测试覆盖了中文大结果产物、正文隔离、错误 ACK、授权变化和产物删除。工具调用与事件接口尚未闭环，未开放的接口继续拒绝执行。

任务产物确认回包丢失后，同一请求可以向所有者重新读取原子提交的索引与正文。只有原授权、任务、定义、产物版本、完整正文与请求元数据全部一致才恢复成功引用，不增加索引版本、不再次写入。相同请求编号提交不同正文或元数据、正文损坏、删除标记和失效授权均拒绝恢复。真实设备数据端口和产物定向测试已验证重复确认与冲突拦截。

提供者切换联测使用实际 TLS 1.3、设备身份签名、本机代理和 WebSocket 通道，配对审批及业务响应由可控服务提供。等待 C 批准时中断 A 到 B 的现有 SSE；就绪后新请求使用 A 在 C 的独立身份直接到 C。联合 SQLite 策略和所有者存储验证旧管理员失效、旧执行失效、B 的原数据保留且 C 未收到迁移。设备凭证持久保存最近一次提供者变更编号和原 Core 身份，网页及手机即使没有旧前端记录也能恢复 B→C 提示；重复读取同一变更不会反复中断。该测试不替代三台实际业务 Core 或真机扫码验收。

生产 Core 的任务运行配置已接入完整所有者端口与原授权恢复器。配置在内核构造时固定，通过一次性原子绑定接入实际服务，未绑定时拒绝执行，运行期间禁止更换依赖。恢复只接受当前机器自己的 Core 授权域；先恢复策略与设备调用权限，再读取远端角色，角色复核避免递归触发自身。实际 TLS 设备通道验证了生产绑定入口、角色复核、所有者任务输入确认及读取，并确认 Core 未保存设备正文。设备端受托异步任务的持久证明、远端暂停恢复、宿主工具及事件接口仍未完成，业务门禁继续保持关闭。任务结果、进度和检查点读取新增持久授权快照复核，快照过期、替换或授权降级均拒绝读取正文。

本轮定向测试覆盖设备策略独立、管理员显式授予及失效、跨设备目标模式、执行取消与迟到提交拒绝、并发版本更新、存储原子性和幂等、角色隔离、来源删除与索引拒绝、回写确认清理、跨设备请求编号隔离及重启退避、二维码响应与无效地址拦截、普通设备模型配置权限和相机生命周期。另执行前端及桌面类型检查、手机源码静态检查。未构建安装包或安装手机应用，不能将静态检查视为真机扫码验收。

Task Host 的检查点保存改为请求确认，Go 宿主在所有者写入及任务元数据提交成功后才回复版本 ACK。客户端收到正确 ACK 前不更新检查点和游标，确认失败后拒绝继续推进版本。暂停请求与保存确认重叠时先等待正在进行的确认，再提交最终检查点；重复暂停被拦截，暂停超时后不再发布迟到成功。入口 RPC 校验检查点内容游标与保存版本一致。实际 TLS 目标版本查询和所有者确认联测覆盖两端安装代次不同、重复确认及目标升级后拒绝重派。

固定入口指纹的任务要求 Task Host 在握手时声明入口字节校验和检查点保存确认能力，缺少任一能力即在执行前拒绝。核内任务数据库追加独立版本化迁移，补齐租约编号、到期时间和心跳时间；任务 CAS 同时保存执行目标、执行尝试及解析信息，旧迁移不改动。任务所有者 RPC 使用当前配对设备身份签名和 TLS 1.3，检查正在执行的原任务、持久授权、派发调用编号、已领取租约、会话和连接版本，连接或授权在确认期间改变后拒绝返回正文。租约同时以当前连接的派发管理器为依据，服务重启不会恢复旧派发权限。

统筹模式的设备受托任务使用 Core 原任务元数据直接运行，不创建第二份本地任务记录或队列。入口、安装代次和完整目标定义持续复核；存储、产物、进度和检查点通过限定的所有者 RPC 使用 Core 同一份数据。远端恢复携带已确认检查点正文并验证游标，进度继续 Core 已保存序列；大结果只提交 Core 产物引用，重复终态重新验证产物仍有效。错误确认、进程未确认结果和取消期间的未确认结果均报告结果未知，Core 不写伪造失败终态、不确认派发已完成，后续只允许核对所有者结果或确认检查点后人工恢复。原 Task Host 源码的真实 Node 子进程覆盖存储、检查点、恢复游标、进度和大结果引用，实际 TLS 所有者接口覆盖设备认证、租约和连接拦截。关闭统筹模式的受托执行、远端暂停及完整生产联测仍未闭环，业务门禁保持关闭。
