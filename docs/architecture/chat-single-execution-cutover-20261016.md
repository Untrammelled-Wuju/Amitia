# 聊天统一执行与旧入口退役

本轮目标是将现有聊天功能与调用方迁入统一授权执行链路，并删除旧入口、旧回退与旧适配实现。保留现有页面、聊天记录、统一调度底座、任务账本、工具注册、模型配置与交付能力。

## 已确认的生产入口

| 入口 | 当前依赖 | 整合目标 |
| --- | --- | --- |
| 手机端和电脑端聊天 | Owned 优先，仍有旧 HTTP 回退 | 只调用统一 Owned 主链，失败明确返回 |
| 统计、清理、导出、摘要与上下文预览 | 旧 chats/system/agent 路由与部分 Owned 查询 | 基于真实 Owner 的统一管理接口 |
| 渠道消息与 Agent webhook | UnifiedEntry 到旧消息处理器 | 来源适配到统一授权执行服务 |
| 语音会话 | VoiceEntry 到 UnifiedEntry | 保留语音控制并使用同一执行主链 |
| 连续任务唤醒 | continuityWakeDispatcher 到 UnifiedEntry | 核验绑定范围并调用统一执行 |
| 插件、游戏事件唤醒 | gameHostAgentWakeupAdapter 到 UnifiedEntry | 保留事件隔离、工具和交付语义 |
| 多 Agent Worker | Owned runner 和旧 runner 回退 | 统一后台执行及可验证恢复 |

## 不能遗漏的能力

- 模型选择、推理设置、消息样式、附件、引用、流式事件和真实保存确认。
- 技能目录、轮次清理、上下文贡献、工具进度、权限审批、回复后处理和消息输出规划。
- 请求幂等、明确取消、断线后台继续、撤权停止与重启恢复。
- 旧聊天记录仍须在真实所有者上提供管理能力；禁止将远程所有者请求直接交给 Core 本地旧库。
- 清理聊天时保留记忆与同时清理记忆必须维持原有可选语义。
- 来源适配可保留，旧执行器的兼容包装不得成为最终架构。

## 工作顺序与进度口径

1. 调用与能力清单，锁定模块边界：10%。
2. 统一执行契约与可信来源授权：20%。
3. 迁入工具和插件生命周期：30%。
4. 统一历史与管理能力：40%。
5. 两端完成接入、移除回退：50%。
6. 语音、渠道和内部唤醒迁移：60%。
7. 多 Agent、取消与恢复收敛：70%。
8. 删除旧入口、适配和失效注册：80%。
9. 定向回归、真实入口及归属验证：90%。
10. 当前源码构建、重启与发布验证：100%。

百分比代表上述工作包完成度，不代表代码行数或预估剩余时间。未通过真实调用和删除检查，不能标记全部完成。
