# 更新日志

26.2.0-beta.19

本次更新相较 26.2.0-beta.18，重点完善多角色群聊、手机渠道工作区、插件自动刷新与运行稳定性，并修复群聊消息归属、实时排序、头像显示和插件生命周期问题。

## 更新内容

### 多角色群聊

- 桌面端、Web 与 Android 新增“多角色讨论”：在至少两名有效成员且允许角色互相 @ 时，角色会按成员顺序轮流发言并回应当前议题及上一位角色。
- 讨论轮数沿用群聊自动接话上限，从当前对话角色开始轮转；成员顺序、成员身份或群设置发生变化时会立即停止后续发言。
- 标准群聊模式保留原有并行回复和点名接话；每个角色的上下文截止到触发消息，避免同一轮角色提前读取其他角色尚未完成的回复。
- 群聊回复按投递身份独立流式展示，使用稳定的 `deliveryId`、`deliveryIndex` 去重与排序，不再出现重复气泡、乱序或整轮回复被误判为单聊发送中。
- 群聊保存增加会话级互斥与最新序号校验，多个角色同时完成时不会互相覆盖最后消息序号。
- 默认名称的群聊会在首轮成功回复后根据角色发言自动生成标题；用户手动设置的标题不会被覆盖。
- 群成员列表使用裁切头像，并拒绝把当前角色再次列为可邀请成员。

### 会话与实时状态

- 会话切换失败时增加有限重试；切换会话会同步清空旧群成员、讨论模式和回复目标，避免串到其他会话。
- 自动生成会话标题后会刷新侧边栏标题，群聊与单聊均保持当前页面标题一致。
- 实时回复、持久化消息和群投递行使用稳定 UI 键合并，减少刷新快照后出现重复消息或状态回退。
- 消息分页改为按字节限制：普通消息单页最多 2 MiB，检查点单页最多 1 MiB；超出时返回游标继续读取，降低长对话加载失败风险。
- 群聊资源返回前会移除持久化头像字段，再由当前角色目录补全，避免角色换头像后历史记录继续显示旧图片。

### 手机渠道工作区

- 渠道消息页改为从已启用插件动态发现渠道，显示渠道入口、当前渠道会话、群聊/私聊数量、消息数和最近活动。
- 单会话渠道直接内嵌只读消息；多会话渠道提供会话列表和正文页，正文复用统一消息渲染能力，并显示明确错误与空态。
- 渠道插件页升级为标签式工作区，包含“插件页面”“消息统计”“设置”以及插件注册的自定义页面；访问过的页面可保持挂载。
- 新增渠道沙箱设置，可控制隔离和联网权限，并显示沙箱目录、工作区标识与生效范围；直接从渠道新进入的会话会使用沙箱。
- 手机端支持插件声明的受控外部 Web 页面，限制允许的 Origin，并显示加载进度和错误回退。
- “我的”页仅在已注册渠道插件时显示“渠道消息”；扩展中心不再重复显示已归入渠道工作区的插件卡片。

### 插件页面与自动刷新

- Schema UI 新增 `refreshIntervalMs` 生命周期字段，后端、传输层和 Android 渲染器统一保留并校验 1–60 秒范围。
- 移动端页面可定时执行 `onRefresh`，仅在应用前台且路由可见时运行，并阻止重叠请求；切换文档或离开页面会自动取消计时器。
- 手机页面显示 5 秒状态刷新；QQ Bot 与微信根据在线状态切换“连接/断开”按钮，微信补充账号、提示、错误和二维码状态。
- 移动 Schema 增加不确定进度、网格宽高比、按钮组绑定、状态文本和紧凑布局支持，减少动态插件页空白与渲染错位。
- 微信退出登录与停止轮询改为可中断流程，不再等待旧轮询链路结束后才返回。

### QQ 个人号与插件运行

- QQ 个人号升级到 `0.2.177`：持久化最近 2000 条入站/出站消息和 1000 条运行日志，重启后仍可查看接收数、回复数与最近活动。
- 被触发规则忽略的消息也会记录到渠道活动，只有实际触发回复的消息才进入 Amitia 对话管线。
- 未匹配触发条件的消息可用于渠道统计，但不会误启动模型回复。
- OneBot 请求响应绑定到原 WebSocket，多客户端同时连接时不会把动作结果串给其他连接。
- 原生模式要求先完成 SnowLuma 安装；插件未启用或未安装时不再自动启动原生运行环境。
- 插件卸载时只清理由插件清单登记且属于该扩展的运行时目录与链接，并通过路径逃逸、符号链接和归属校验保护其他插件数据。
- QQ Bot 插件升级到 `1.0.20`，微信插件升级到 `1.0.26`。

### 初始化与界面

- 首次启动改为简洁白底引导，移除星空背景、长篇入场动画和延迟跳转；保存失败会在当前步骤直接显示错误。
- 开始使用按钮在保存期间显示“正在保存”，完成后直接进入聊天，不再先进入与实际保存结果脱节的过渡页。
- 侧边栏“最近”调整为“聊天”，会话移出项目时使用“移回聊天”，与现有导航语义一致。
- 插件输入扩展为空时不再保留空白容器；导航头像统一使用透明底和完整裁切显示。

### 运行与构建可靠性

- Android Runtime 固定引入 Ubuntu `libatomic1`，构建和安装校验会检查 `libatomic.so.1` 的文件类型、链接及哈希。
- 管理端运行轨迹仅加载会话、消息和检查点资源，避免无关记忆或群资源进入大快照。
- 插件卸载时补齐运行时所有权检查并清理已登记资源，降低残留数据和孤儿目录风险。

## 重要兼容说明

- “多角色讨论”需要群聊至少两名有效成员并开启“允许角色互相 @”；关闭该设置后讨论按钮不可用，进行中的讨论会在下一轮开始前停止。
- QQ 个人号本版本的正式兼容范围为 Windows、Linux、macOS 与 Web；未完成的 Android/iOS 原生 SnowLuma 运行实验已从最终源码和插件清单移除。
- 渠道沙箱对已有会话保持原工作目录，仅对启用策略后从该渠道新进入的会话生效；插件重启后完全生效。

## 适用范围

Windows、macOS、Linux 桌面端；Web 客户端；Android arm64-v8a；本地 Core 与设备归属运行模式。

QQ 个人号 `0.2.177`、QQ Bot `1.0.20`、微信 `1.0.26`。

## 升级说明

- 本版本基于 beta.18 之后全部源码提交整理，升级后会自动保留现有会话、角色、插件和设置数据。
- 升级后建议重新打开群聊以刷新成员、讨论模式和自动标题状态。
- QQ 个人号在 Android/iOS 上不再展示插件入口，也不会再提供本版本中已撤回的手机原生 SnowLuma 运行链。
