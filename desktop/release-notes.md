更新日志

26.2.0-beta.10

知识库与文档

- 新增独立知识库入口，桌面端、Web 与手机端可上传、查看、检索和管理当前空间的知识源。

- 支持 TXT、Markdown、CSV、JSON/JSONL、DOCX、XLSX 和 PDF；保留页码、段落、行与工作表等原文位置。PDF 可在 OCR 依赖可用时识别扫描文字。

- 支持知识源多版本上传、重建索引、版本回滚与历史版本清理；新版本切换前仍使用当前活动版本。索引任务可重试或取消。

- 补充旧版 DOC 文档导入，在已安装 LibreOffice/soffice 时转换解析；原始文件保持不变。

- 桌面端可分页查看文档结构大纲，并从知识单元或检索结果读取邻近上下文，精读内容来自已解析的指定版本。

- 知识源支持删除；删除与过期版本清理联动处理索引，避免已删除内容继续作为有效检索证据。

检索与调查

- 新增自动选择及 NONE、FAST、DEEP、AGENTIC 检索档位，支持当前有效、历史时点与全部时段查询。

- 结合精确、词法与向量检索，支持重排和上下文扩展；向量索引不可用时降级检索并显示状态。

- 新增 search_knowledge 与 read_knowledge 工具，支持定位和读取知识原文；读取范围受知识源与权限约束。

- 新增有边界的知识调查流程，限制轮次、搜索次数、读取量与总时长，支持来源白名单、取消和无进展终止。

- 新增证据充分、证据不足／无证据、证据冲突状态；检索允许返回零条结果，比较问题会检查不同来源的覆盖情况。

- 支持按有效期、替代关系与冲突组处理证据，历史查询结合指定时点筛选，冲突证据会显式提示。

- NONE 档位可跳过知识检索；深度检索支持问题拆解与查询改写，结合去重和来源多样性选择证据。

引用与聊天体验

- 知识引用使用 [K数字] 编号，与网页引用分开；实际出现在回复正文中的知识引用会保存为快照。

- 引用快照随消息同步到实时事件与历史记录，多端断线恢复后仍可回看；后续索引重建不改写已保存的历史引用。

- 聊天可识别知识查询、文档检索和原文定位意图，避免普通陪伴交流被无条件检索覆盖。

- 检索、原文精读与调查过程统一展示为当前轮次的持久化任务，支持进度恢复与事件重放。

- 加强引用来源、版本、定位与摘要校验，排除代码片段及无证据编号，减少错误和重复引用。

- 修复已完成、失败或中断的回复被迟到启动、审批或文本事件重新激活的问题；取消后不再追加过期文本。

- 修复历史记录、活动快照和实时事件合并时的状态与内容回退，保留较新消息块，避免已结束回复重新显示为生成中。

- 区分引用字段缺省与显式清空：缺省时保留已保存引用，新结果明确为空时移除旧引用，避免重复重放或残留。

- 引用链接过滤敏感查询参数，限制协议、定位字段和快照大小；Markdown 普通链接与图片语法不再误识别为引用。

数据与维护

- 新增知识源、修订、分块、索引任务与引用快照的数据结构及迁移，补充租户隔离与版本有效期管理。

- 新增检索轨迹、性能指标、基准记录与索引健康查询，便于排查检索效果和任务异常。

- 新增向量一致性检查、孤儿向量分页巡检、复核与审计记录，并提供人工恢复审查能力。

- 索引写入与删除任务采用租约领取、续约、退避重试和积压检查；新增一致性修复与过期版本清理入口。

- 恢复审查补充申请、人工通过、撤销、有效期和操作轨迹核验，禁止申请者自批；计划检查为只读，不自动执行向量删除或恢复。

- 基准记录补充召回率、排序质量、无答案准确率、延迟分位数和错误率，并展示性能目标与样本是否充足。

- 新增检索策略、精读和调查开关，以及解析、OCR、索引与检索的并发、大小和超时配置；运行状态可查看生效配置。

- 公共工具体系新增 knowledge.read 权限及知识工具模块，统一约束知识访问，与记忆、世界书和任意文件路径读取分开。

修复与平台适配

- 修复 Android 发送聊天前，因轮次和执行标识尚未生成而误报角色、权限或数据归属缺失的问题。

- 修复桌面端首次进入或刷新主动任务等扩展页面时出现 404 的问题，补充旧主动任务地址跳转。

- Core 构建与资源定位适配 Windows、macOS、Linux 及 x64/arm64 目标；新增 macOS 全服务启动脚本，改进 Windows 文档替换流程。

适用范围

- 版本：26.2.0-beta.10；Android versionCode：16。覆盖桌面端、Web、Android 与共享后端的相关源码变更。

26.2.0-beta.9

渠道与插件

- 桌面端渠道消息中心改为按渠道分组展示，微信、QQ 和个人微信等已安装渠道即使暂无会话也会保留入口；历史会话会按会话标识自动归入对应渠道。
- 渠道消息支持同时展示多张图片、视频、语音和文件附件，并显示实际发送者名称；图片加载失败时可以直接打开原图，不再只显示空白或占位文字。
- 修复媒体消息的 `[图片]`、`[语音]` 等占位文字与附件重复显示的问题。
- 渠道消息追加改为走设备所有权运行时，保留一次写入多段内容（文字、图片、语音、视频和文件）的能力，并增加幂等重放；同一请求重放不会重复写入。微信渠道发送增加投递去重，网络重试不会重复发送同一条消息。
- 修复渠道投递积压超过 64 条时，启动恢复只处理第一批的问题；现在会按游标逐页处理全部待投递消息。
- 微信渠道插件升级到 1.0.19，QQ 渠道插件升级到 1.0.17。连接页会合并重复状态请求，扫码或连接中加快刷新、普通状态降低刷新频率，页面隐藏时暂停轮询。
- QQ 渠道完善私聊和群聊接入，支持接收图片、语音和视频，发送图片和语音；同一会话的连续消息按顺序处理，避免并发回复错乱。

扩展与插件

- 扩展 Provider 在核心重启后会重新激活，并关联恢复后的运行时实例；已启用的渠道插件无需重新安装或手动启用。
- 扩展恢复时会重新关联运行时结果；恢复失败时保留“需要恢复”状态并记录原因，不再静默跳过。

聊天与设备服务

- 桌面端数据目录改为稳定定位：首次启动会记录实际数据目录，新安装默认使用 `%LOCALAPPDATA%\AmitiaData`，已有旧安装目录数据会继续沿用；更换安装路径后不会重新生成设备身份。
- 当记录的数据目录不存在时，桌面端会拒绝启动并返回原路径错误，避免静默创建新目录并生成新的设备 ID。
- 设备调用、任务提交和语音通话的提示统一区分本机 Core 与云端服务，本机模式不再误称云端。
- 没有正在进行的回复时，核心或权限变化只提示服务或数据归属已变化，不再误报“当前回复已中断”。
- 临时断线恢复后会清除旧的不可用提示；核心地址实际变化时才刷新连接，启动中和就绪的同地址状态不再触发无意义的会话中断。
- 侧边栏并发加载会合并为一次请求，服务切换期间被取消的加载会自动重试，减少侧边栏闪烁和重复请求。
- 服务切换、角色切换等预期状态不再冒泡为界面异常，避免在切换瞬间弹出内部错误。
- 角色状态、关系和需求更新改为在消息落库后提交，避免消息写入失败时状态先发生变化。

反馈与诊断

- 报错反馈会同时收集本机 Core、插件和扩展目录中的运行日志，默认保留最近 500 行运行日志和最多 500 条报错行。
- 日志识别改为优先读取结构化日志级别，能够区分数值 level、`level=warn` 等格式，减少把成功日志误判为报错，也减少漏掉 warning。
- 多个日志文件会按时间交错采样，避免只读取单个大文件；提交前仍会继续脱敏令牌、邮箱、手机号、用户名和本机路径。
- 反馈弹窗和设置页的说明同步更新为“本机与插件运行日志”。

底层与清理

- 聊天和渠道消息统一走设备所有权运行时的消息追加接口，支持多段消息、投递组和幂等重放；旧的聊天消息追加路径和旧网页聊天接口已移除。
- 移除启动时的会话事件历史回填，减少启动阶段不必要的扫描。
- 版本号更新为 26.2.0-beta.9，Android 端 versionCode 更新为 15。

26.2.0-beta.8.1

进程管理与稳定性

- Windows 下 AmitiaCore 改为由 Job Object 托管。核心以挂起状态创建，加入设置了 KILL_ON_JOB_CLOSE 的 Job 后再恢复执行；关闭 Job、supervisor 退出或桌面端退出时，系统只结束 Job 内的核心进程树，不再按 PID 猜测要结束的进程。
- 桌面端移除了 taskkill /PID /T /F 的强制清理路径。停止核心时先向 supervisor 发送 shutdown 控制指令，由 supervisor 终止 Job；需要兜底时也只结束 supervisor 子进程，交由 Job 生命周期清理核心。
- supervisor 会把真实核心 PID 通过 AMITIA_CORE_PID 返回给桌面端。端点归属、健康检查和 pid 文件清理都使用真实核心 PID，避免把 supervisor 或复用 PID 误认成核心。
- 核心端点增加失效、epoch 和实例身份判断。旧端点失效后，请求会等待新端点；后续会话会发现核心实例变化并自动重建，不再继续使用旧核心的会话令牌。
- 后端请求增加 ECONNREFUSED、ECONNRESET、EPIPE 的有界重试。重试前清理旧端点并等待新端点，避免核心重启窗口直接向界面抛出原始网络错误。
- 获取后端鉴权头的 IPC 错误转换为“Amitia Core 正在启动或重启，请稍后重试”，不再把 Error invoking remote method 和内部端口暴露给用户。
- 后端单实例检查改为严格校验可执行文件路径，删除“任何 server.exe 都是 Amitia Core”的宽松匹配。PID 文件指向其他程序时只清理陈旧记录，不会结束该程序。
- 只删除当前核心 PID 对应的 endpoint.json；异常退出、supervisor 退出和更新安装时不会误删其他实例的端点。
- 安装器清理旧进程时使用大小写不敏感的安装目录匹配，并在 Stop-Process 后等待进程退出，减少覆盖安装时文件仍被占用的问题。
- 更新安装前先停止本地运行时、关闭核心并等待退出，再调用 quitAndInstall；更新尚未下载完成时不再允许触发安装。
- 修复本机 Core 模式下记忆统计绑定了空的推理审批上下文，导致访问 Usage 按天统计时出现 nil 指针 panic、高级系统页面返回 500 的问题。本机模式没有独立推理审批上下文时直接跳过审批，Usage 统计和后台记忆后处理恢复正常。

扩展与插件

- 修复微信插件“微信连接”页面 404：扩展页面传给 schema/session 接口的 contributionId 改为后端实际注册的裸 ID，不再重复拼接 extensionId。
- 扩展页面宿主增加请求 token 和 disposed 状态。卸载后不再写回旧页面结果，不再重新调度轮询，也不会让旧页面的轮询链继续读取新页面的会话。
- 扩展页面只保留一条轮询链，重试和路由切换会先取消旧链；关闭页面时按打开时的会话 key 注销，避免路由变化后注销错 key。
- Schema UI 加载增加卸载保护。组件卸载后到达的 schema 响应、校验结果和错误不会再写回已销毁的组件。
- 修复 404 页面跳转后扩展页面继续请求、定时器叠加和渲染进程内存持续增长的问题。
- 主动任务插件运行时改为云端托管，界面贡献保留在设备端；ui.notify 权限改为全局作用域，并同步更新包校验规则。
- 世界游戏示例插件升级到 1.0.5，补齐 worldgame.command 与 move RPC，声明 service.runtime.execute 权限，修复 GameHost 启动服务运行时和移动指令处理。
- 修复安装版桌面端打开插件页面一直转圈的问题：自定义 app 协议现在会把插件页面资源请求转发到本机 Core，插件 HTML、脚本和样式可以正常加载，页面能够完成握手并渲染。

聊天与多端同步

- 聊天轮次历史从数字 before 改为游标分页。桌面端和移动端使用 nextCursor 继续加载旧轮次，长会话不会因为序号变化或消息插入而重复或漏读。
- 新增队列状态查询、排队聊天恢复和重试排队。重试会重新读取原用户消息，生成新的请求 ID 并进入队列，不再直接启动一个可能重复的执行。
- 聊天事件流增加会话归属、事件序号连续性校验和缺口检测。检测到事件缺口时要求重新加载快照，避免 UI 在缺失事件的基础上继续拼接。
- 目标轮次不在首批快照时，会沿 checkpoint 游标继续加载，直到找到目标轮次；干预、审批和重试都校验轮次归属。
- 设备所有权聊天运行时从活动轮次的 blocks 恢复文本、工具调用、工具结果、错误项、参数、结果、错误码和耗时，历史展示不再只有空 items。
- 轮次序号改为基于创建时间的毫秒值，避免并发写入时简单索引导致顺序漂移；批准记录同时匹配 requestId 和 turnId。
- 父轮次恢复统一交给设备所有权引擎对账。无法确认执行是否完成的轮次进入人工处理，不自动重放工具或重复写入。
- 聊天主链路切换到设备所有权运行时，移除旧的 unified entry、chat handler 和 delivery store 双路径，减少不同入口状态不一致。
- 聊天补充生命周期事件、推理耗时、世界书提示、引用审计和工作区校验；工具执行、模型回复和最终失败会记录更完整的恢复信息。
- 设备协同聊天管理补充标题、消息 ID、原因、序列范围和分页参数校验，减少异常参数进入运行时。
- 前端会话运行时同步适配游标分页、队列状态和新的轮次数据结构。
- 角色配置刷新改为不打断回复。检测到角色 revision 变化时只显示“角色配置已变化”的轻提示，不再中止正在生成的回复，也不会清空当前对话；下一条消息发出时提示自动消失。
- 角色切换后的侧边栏同步、摘要加载和后台刷新补充异常处理，切换角色不会再产生“原回复已中断”的未捕获 Promise 异常。

- 多端聊天统一：手机端、电脑端和网页端使用同一套聊天流程，减少一端发送成功、另一端状态不同步的问题。
- 完整消息能力：支持模型选择、推理设置、流式回复、附件、引用、文件、工具进度、权限审批和保存确认，日常聊天和复杂任务都能在同一会话中完成。
- 模型协议选择：语言模型可以选择 Chat Completions 或 Responses 协议，兼容不同服务商的接口能力。
- 生成控制：生成过程中可以停止、重试或补充新的指令，模型调用失败时会保留服务端返回的具体错误，方便判断是网络、密钥还是服务问题。
- 多媒体消息：图片、视频、文件、语音都可以发送、预览、播放和下载，聊天中可以直接查看或播放媒体内容。
- AI 生成图片：可以按文字描述生成图片，结果会保存为受管理的图片资源并直接显示在回复中。
- 图片文字识别：可以提取图片中的文字，支持聊天截图、文档照片和画面文字的识别。
- 联网媒体结果：联网检索可以返回图片和媒体结果，并携带缩略图、尺寸和来源信息。
- 文件格式支持：聊天文件支持 UTF-8 文本、Markdown、CSV、JSON、XML、PDF 和 DOCX，图片支持 PNG、JPEG、GIF，视频支持 MP4、QuickTime 和 WebM。
- 语音转写：语音消息可以转成文字，并随原消息保存，方便回看和继续对话。
- 连续工具执行：Agent 会持续调用工具直到得到最终答复或触发终止条件，不会因为固定轮数提前结束任务。
- 同轮多工具调用：只读且重复执行不会改变结果的任务可以并行处理，写入和会产生副作用的工具按顺序执行，兼顾速度和安全性。
- 长上下文压缩：上下文接近模型窗口上限时，会压缩较早的工具执行内容并继续当前任务，减少长任务中途断开。
- 多 Agent 协作：复杂任务可以拆给多个 Agent 后台执行，支持查看子任务进度、等待结果和取消任务。
- 多 Agent 任务隔离：每个子任务使用独立会话和工作目录，避免多个 Agent 同时修改同一批文件造成冲突。
- 子任务审核：子任务完成后仍需用户确认，系统不会自动把结果当成最终答复，也不会自动合并代码。
- 权限模式继承：子 Agent 会继承当前会话的权限模式，不能自行提升到更高权限或绕开用户审批。
- 后台继续执行：关闭聊天页面后任务仍可继续；重新打开应用时能够恢复任务状态和已经完成的步骤。
- 安全恢复：应用意外退出后可以从检查点继续任务；无法确认是否已经执行的工具不会自动重放，避免重复写入或重复产生副作用。
- 完成前校验：Agent 结束任务前会检查是否仍有待验证步骤，没有完成的操作不会被直接标记为成功。
- 统一工作台：在聊天中集中查看文件、文档、终端、浏览器、任务和检查点，处理复杂任务时不必频繁切换页面。
- 工作台任务详情：可以查看任务进度、检查点历史和审核提示，方便确认长时间任务执行到了哪一步。
- 任务暂停与恢复：任务中心支持暂停、继续和从检查点恢复；“需恢复”和“需人工干预”会单独提示，用户确认旧执行停止后再恢复。
- 远程浏览器观察：可以查看目标设备上的浏览器画面；只有取得控制权限后才能点击和输入，设备断线或权限变化会停止操作。
- 终端会话恢复：重新打开工作台时可以恢复仍可用的终端会话，或继续查看旧会话的中断状态和退出码。
- 终端输出与安全粘贴：终端支持 ANSI 颜色和滚动输出，粘贴内容会过滤不可信控制字符，避免意外执行隐藏命令。
- 角色切换分隔线：在同一会话切换角色时会显示明确分隔，用户能看出从哪条消息开始使用新角色。
- 项目目录管理：项目支持重命名、添加多个文件夹工作区、设置主根目录、置顶、在文件管理器中打开和从侧边栏移除。
- 项目会话展开：项目下的最近对话可以展开显示或收起，项目较多时侧边栏仍然容易浏览。
- 聊天记录管理：支持聊天记录导入、预览、批量确认、导出、清理和摘要，迁移或整理历史对话更方便。
- 清理范围可选：清理聊天时可以选择只删除消息，或同时清理关联记忆，避免误删仍然需要的长期信息。
- 消息编辑与删除：支持编辑、删除和引用消息，并校验当前角色、会话和数据归属，旧页面不能修改已经切换的数据。
- 自动化状态提示：对话页会显示当前自动化执行状态，用户能知道 Agent 是在等待、执行还是已经完成。

主动任务与提醒

- 统一主动任务入口：聊天创建、手动创建和插件创建的任务统一使用同一套提醒与执行记录，避免不同入口显示不同状态。
- 多种重复规则：支持一次、每天、每周、每月、工作日和固定间隔任务，重复任务触发后会自动计算下一次时间。
- 主动策略设置：支持主动程度、规则、角色级配额、免打扰、最短间隔和未回复冷却，减少过度打扰。
- 每条提醒独立设置：每条任务可以单独设置时区、发送渠道、结束时间、最多次数、每日上限、随机延迟、免打扰时段和是否发送系统通知。
- 主动任务历史：可以查看创建时间、触发记录、执行结果和失败原因，问题发生时更容易判断是时间、权限还是连接问题。
- 历史清理：可以清理已经结束的执行明细，同时保留必要的触发记录和未完成结果，避免历史无限增长。
- 任务结果状态：消息保存、渠道发送和系统通知分别显示实际结果，排队、部分成功、未知和失败不会混成同一种成功状态。
- 提醒通知：提醒可以显示为系统通知，用户可以设置是否接收提醒通知以及免打扰时间。
- 提醒操作与状态：可以暂停、恢复或立即执行提醒，并查看调度器状态、到期数量、今日发送数、失败数和队列压力。
- 设备级调度：云端任务不依赖手机一直在线；设备离线时不会把未展示的通知当成已经送达。
- 持续事项：长期任务可以跨对话保存进度，暂停后不会继续生成，恢复时从前一状态继续，并按原设备或当前 Core 保存。

时间与地区

- 时间感知开关：可以控制是否把真实日期、时间和日内时间段提供给普通聊天，关闭后不会向聊天提示注入时间上下文。
- 时区管理：支持固定时区和设备时区，定时检测设备时区变化并提示确认，避免跨时区后提醒时间出错。
- 语言与地区：可以设置区域语言和每周起始日，日期显示和按周计算更符合当地习惯。
- 安静时段：可以设置不接收主动投递的起止时间，主动任务会按用户当地时间判断是否允许发送。
- 节日与纪念日感知：可以启用节日、纪念日、关系纪念日和时间段理解，让角色更自然地处理日期相关对话。
- 记忆时间共振：时间信息可以影响相关记忆的检索排序，使同一时期发生的事情更容易被一起回忆。
- 时间锚点：可以记录生日、纪念日和计划，支持周期、每年、单次、具体时间和时间范围，并查看当前时间快照。

设备协同

- 扫码和手动配对：设备可以通过二维码、手动地址或一次性配对码接入，减少复制地址和配置凭据的操作。
- 重复设备拦截：系统会阻止添加自身、重复添加、反向循环添加和并发领取，避免设备列表出现重复项或错误连接。
- 设备独立角色来源：每台设备可以选择使用本机角色或当前 Core 的角色，不必因为切换设备而重新配置全部角色。
- 数据归属明确：聊天、记忆和持续事项会按照当前统筹模式保存到设备或 Core，用户可以知道数据实际保存在哪里。
- 模式切换保护：切换统筹模式会先由当前 Core 确认，正在生成的回复会中断，避免旧归属继续写入新数据范围。
- 历史数据不迁移：切换设备不会自动复制或迁移原设备数据，历史记录继续由原设备管理，降低隐私数据被意外复制。
- 跨设备任务：任务可以发送到指定设备执行，并支持暂停、恢复、取消、查看历史和下载结果。
- 设备能力授权：调用其他设备前可以选择目标设备和角色，并按调用方、目标和具体能力授权；权限变化后会要求重新选择。
- 设备任务目录：可以选择目标设备上已经安装且有权执行的任务，并查看来源任务和版本，不需要在另一台设备重复配置。
- 设备能力路由：系统会根据任务内容选择具备对应能力的设备，目标设备不可用时明确拒绝，不会悄悄切换到其他设备。
- 服务切换确认：从一台设备切换到另一台设备时，需要独立授权和确认，新设备不会继承旧设备的管理权限。
- 服务切换提示：聊天使用的设备或 Core 发生变化时会提示前后提供者，并暂停旧任务，避免旧设备结果混入新会话。
- 管理员权限控制：管理员必须由当前 Core 明确授予；解绑、撤权或更换 Core 后权限立即失效。
- 设备状态集中显示：设备、平台服务和管理员状态集中管理，连接异常或授权失效时更容易发现。
- 设备同步状态：可信设备会显示最近同步进度，已撤销设备会明确标记为不再同步，避免误以为数据仍在更新。
- 设备运行时探测：可以单独检查某台设备的运行环境状态，确认在线、离线和运行时异常。
- 设备移除与解绑：可以移除设备、解除当前设备的云端绑定并清理本机凭据，不再使用的设备可以从列表中彻底断开。
- 解绑不删除个人数据：解除云端设备绑定时只撤销设备凭据和连接权限，不会删除个人 Space 中的聊天或角色数据。
- 本机配对权限恢复：当前 Core 的配对权限失效时，可以由本机所有者重新确认并恢复配对能力，不会改变其他设备的授权状态。

记忆

- 六个记忆入口：记忆、画像、情景记忆、图谱、时间线和世界书继续集中展示，常用功能更容易找到。
- 记忆来源切换：可以查看当前 Core 的数据，也可以查看原设备保留的历史角色记忆，历史数据不会迁移到当前 Core。
- 多种记忆分类：记忆总览区分候选、工作、情景、事实、偏好和关系等类型，筛选时可以只查看固定记忆或指定状态。
- L1-L5 记忆等级：不同重要程度的信息使用不同强度、保留时间和衰减规则，避免所有内容长期占用相同权重。
- 固定记忆：重要信息可以固定保存，不会被自动提取、强化或等级衰减覆盖。
- 自动强化与衰减：记忆会根据使用频率和时间自然调整强度，长期不用的信息可以淡化或归档。
- 记忆操作：可以固定、停用、归档、恢复或删除记忆，并按类型、重要程度、生命周期和来源进行整理。
- 候选记忆审核：自动提取的内容先进入候选列表，用户可以审核、编辑、忽略或处理冲突，减少错误信息直接进入长期记忆。
- 统一记忆链路：聊天召回、自动提取、反思、聊天记录导入和模型工具使用同一套记忆数据，避免不同入口产生重复记录。
- 角色画像隔离：角色私有画像不会错误写入全局画像，不同角色之间的信息边界更清晰。
- 世界书：支持正则、精确和关键词匹配，并支持 JSON 导入导出；规则会加入当前对话上下文，帮助角色在特定设定下保持一致。
- 记忆时间线：可以按照来源、类型和记忆类别查看记录，并导出 CSV，了解记忆是如何逐步形成的。
- 真实时间排序：记忆时间线按照记录实际保存时间排序，不会把快照顺序误当成修改历史。
- 角色记忆复用：角色记忆和角色时间线复用当前记忆页面，不再维护另一套相同界面。
- 记忆图谱：可以查看记忆、画像、情景和世界书之间的关联，支持搜索节点、拖拽布局、缩放和平移，方便整理复杂设定。
- 备份与恢复：备份保留记忆等级、固定状态、强度和人工关联，恢复后不需要重新整理重要内容。
- 删除清理：删除来源后不会再生成新的向量、图谱或衍生记忆，减少已经删除的内容重新出现在搜索结果中。
- 记忆范围迁移：可以在角色、来源和共享范围之间调整记忆归属，减少角色切换后找不到相关记忆。
- 角色与全局记忆切换：记忆可以从角色私有提升为全局，也可以降级回角色记忆，方便控制在哪些对话中可见。
- 从对话生成候选：可以选择已保存对话生成候选记忆，再进入审核流程，不需要手动摘录聊天内容。
- 索引状态：可以查看向量和图谱处理数量、待更新数量和失败数量，并手动触发重建。
- 关联删除：删除角色、对话或记忆来源时，会同步处理关联记忆和索引，减少残留内容继续被检索。
- 记忆搜索与筛选：搜索入口位于标题栏，可以按来源、类型、生命周期和固定状态筛选，历史界面更容易使用。
- 记忆卡片精简：卡片只展示实际记忆内容，内部字段不会撑大页面，完整信息仍可在详情中查看。
- 历史记忆界面还原：移动端恢复记忆工具网格、分类标签、卡片和操作按钮布局，同时兼容当前数据来源、搜索和深浅色主题。

数据与备份

- 完整数据导出：支持导出全部数据或指定角色数据，备份文件可以保存到本机。
- 备份作用范围：备份和恢复始终作用于当前设备的本地 Runtime，Cloud 模式下不会直接覆盖共享的 Cloud Core 数据库。
- 本地备份管理：可以创建、查看、恢复和删除当前设备 Runtime 备份，恢复前会提示重新启动应用。
- 配置导入导出：支持导出应用配置，并在导入前预览变更和确认覆盖，减少误操作。
- 长期运行维护：可以立即执行健康检查、清理临时文件、轮转日志、检查数据库完整性和整理数据库空间。
- 长期任务限制：可以设置同时运行的任务数量和超时时间，避免后台任务长期占用过多资源。
- 诊断报告：可以运行一键维护诊断并导出后端诊断报告，便于排查组件或扩展异常。
- 高级系统状态：可以查看 Runtime 模块健康、健康历史、安全审计记录、模型错误和日志文件，并调整审计保留周期或清理记录。
- 日志目录入口：可以快速打开本机日志目录，提交反馈或排查问题前直接查看对应日志文件。

AI 能力与扩展

- 聊天内能力发现：可以直接在聊天中查找和安装 Skill、MCP 与扩展，不需要先离开对话再手动搜索配置。
- 多种 Skill 来源：支持 GitHub、本地目录、压缩包和 SKILL.md，可以导入自己编写或从外部获取的能力。
- MCP 接入：支持官方目录、固定版本软件包以及远程 HTTP/SSE 服务，可以把外部工具和服务接入当前对话。
- 原生插件发现：只展示符合 Amitia 扩展格式的插件包，减少安装后无法启动或页面不兼容。
- 渠道插件消息：渠道插件可以注册独立消息入口和发送能力，只有安装并启用后才会显示对应渠道消息。
- 安装前预览：安装前会展示版本、权限、风险、兼容性和依赖关系，用户可以先确认影响再继续。
- 分步安装：安装、配置、连接验证和启用相互独立，用户能区分“已经安装”和“现在可以使用”。
- 安装状态明确：只安装但尚未启用的扩展会显示“已安装，未启用”，避免误以为能力已经生效。
- 安装失败清理：安装失败会清理本次新增的配置和凭据，不会破坏之前已经存在的服务。
- 扩展更新与回滚：扩展更新时先停止旧运行环境、清理旧定义再替换新包，降低新旧版本同时运行的问题。
- 扩展文件选择：扩展页面可以选择本地文件，表单型插件可以直接完成文件配置。
- 移动端插件界面：手机端使用独立插件界面，不再显示只能在电脑使用的入口。
- 桌面与手机界面隔离：扩展必须声明自己支持的平台，桌面和手机不能共用不兼容的页面或组件，减少安装后布局错乱。
- 表情插件兼容：表情插件同步更新最新扩展格式和页面契约，旧版入口不会在手机端错误显示。
- 可信服务管理：可以查看可信服务状态、启动或停止服务、执行健康检查并解除隔离，本地服务异常时可以直接处理。

通知与移动端体验

- 统一通知系统：消息、提醒、主动消息、来电和执行进度使用同一套通知状态，减少重复推送和状态不同步。
- 通知直接回复：Android 消息通知可以直接回复，不必先打开应用再寻找对应会话。
- 会话气泡通知：新消息可以通过气泡形式显示当前会话内容，快速查看上下文。
- 浮动聊天窗口：在其他页面可以快速打开轻量聊天窗口，查看消息或回复后继续当前操作。
- 锁屏隐私保护：通知支持完整内容、仅发送者和隐藏内容等显示方式，避免敏感正文出现在锁屏。
- 前台消息抑制：用户正在查看某个会话时，不再为同一会话推送重复通知。
- 通知离线回复：网络暂时不可用时，通知回复会先保存在本机，恢复连接后自动发送，不会因为退出应用而直接丢失。
- 后台回复提醒：AI 在后台正常完成回复时可以发送通知和提示音；前台完成、失败或取消的回复不会继续打扰，提示音也可以单独关闭。

- 测试通知：可以发送真实测试通知，确认当前设备首选推送通道和通知权限是否正常。
- 本地模拟通知：可以分别模拟消息、提醒和 Agent 执行通知，在桌面和锁屏直接检查显示效果。
- 浮动气泡权限：可以启用、关闭和配置浮动气泡，并直接打开系统悬浮窗权限设置。

- 执行进度通知：长任务会显示进度或兼容通知，切出应用后仍能了解任务是否完成。
- 多厂商推送兼容：支持系统推送以及可选的小米、华为、荣耀、OPPO 和 vivo 通道，提高国产 Android 设备后台到达率。
- 实时通知优先级：会显示小米超级岛、Android 16 实时通知或普通进度通知的实际可用状态，并提示缺失的系统权限。
- 后台运行设置：支持后台保活、屏幕常亮、后台回复通知和虚拟屏码率设置，长时间执行任务时可以减少中断。
- 后台限制提示：设置页会显示系统省电和流量限制状态，并提示在哪些系统页面检查自启动、后台联网和锁屏断网权限。
- 实时通话：支持语音、视频和屏幕通话，通话内容按照当前角色、设备和服务权限保存，切换服务后立即结束旧通话。

优化

- 统一执行与权限：聊天、语音、渠道消息、连续任务、插件事件和游戏事件使用同一套权限流程，减少某个入口可以执行、另一个入口却提示无权限的问题。
- 消息状态一致：发送、流式回复、历史同步和会话切换统一管理，切换会话后不会出现消息回退、重复或突然消失。
- 会话级设置：可以针对当前会话保存独立设置，不同会话之间不会互相覆盖。
- 聊天输入体验：模型、思考强度、文件夹、权限、语音和发送按钮重新排列，常用操作更集中，输入框不易被遮挡。
- 记忆接口统一：记忆、候选、画像、情景记忆、图谱和世界书使用统一数据接口，页面显示与实际保存内容更一致。
- 记忆范围选择：共享记忆可以选择来源范围，查看和迁移时更容易确认记录属于当前角色还是其他来源。
- 跨设备任务可靠：任务加入租约、检查点、请求去重和提交确认，网络中断后更容易恢复，也不会重复执行同一步骤。
- 任务权限持续校验：后台任务在执行前、执行中和提交结果时都会重新确认权限，撤权后不会继续使用旧权限。
- 工作树安全清理：任务结束时不会强行删除有未提交改动的代码目录，避免用户代码被清理流程误伤。
- 关闭终端不残留进程：关闭终端时会同时结束关联子进程，减少后台残留进程占用资源。
- 管理员权限明确：管理员权限必须由当前 Core 授予，解绑、撤权或更换 Core 后立即失效。
- 敏感信息保护：通知令牌、模型密钥、MCP 凭据和供应商密钥不会出现在普通日志或公开接口中。
- 插件主题一致：手机插件界面和主题强调色跟随当前主题，减少插件页面与主应用风格割裂。
- 已有 Skill 保护：安装或更新能力时不会误删已经存在的 Skill，失败回滚只清理本次新增内容。
- 工具历史注入防护：恢复任务时压缩的工具记录会被当作不可信资料，不会被误当成系统命令执行。
- 日志更清晰：桌面端核心日志按内容分级，正常启动和审计信息不再显示成错误。
- 启动更顺畅：桌面端启动更新检查与页面加载分离，不会因为网络慢或更新服务响应慢而卡在启动页。
- 后续更新更轻量：首次安装保留向导，后续升级直接覆盖原目录，减少重复配置。
- 更新检查更准确：手机端先读取本机安装信息，再检查远程版本，检查失败时也不会显示错误版本。
- 构建来源一致：手机端安装包统一使用项目源码，并从同一份源码生成内置运行环境，降低安装包与应用代码不匹配的风险。
- 运行环境安全替换：手机内置运行环境更新时先完成新包准备和校验，失败时保留原环境，避免更新后无法启动。
- 设备协同连接更稳：设备协同通道不再受系统代理影响，局域网配对和任务传输更稳定。
- 配置整体保存：配置修改使用整体提交，保存中途失败时不会留下只改了一部分的状态。
- 双端真实更新验证：桌面端和手机端均完成检查、下载、安装和重启流程，已安装旧版本的用户可以直接在应用内升级。

移除

- 移除旧聊天备用流程：聊天失败时会明确提示，不再悄悄切换到旧逻辑，避免同一会话出现不同执行结果。
- 移除旧多 Agent 工具入口：统一到当前多 Agent 调度，减少重复工具和权限范围不一致。
- 移除旧语音健康接口：删除不再使用的接口，降低维护成本和误调用风险。
- 移除旧记忆业务模块：记忆、画像和情景数据统一进入当前记忆系统，避免多个模块分别保存同一份信息。
- 移除旧主动消息分支：旧每日重生、角色调试页主动消息和专属通知不再分别运行，统一改为主动任务和统一通知。
- 移除网页旧记忆页面：旧编辑器、旧列表和旧检索界面不再出现，用户只需要使用当前记忆页面。
- 移除手机第二套记忆页面：保留统一入口，减少相同功能在不同页面显示不同数据。
- 移除旧记忆诊断入口：旧诊断和批量验证入口不再出现，避免调用已经停用的记忆接口。
- 移除远程旧同步方式：远程设备不能再用旧方式直接操作完整业务数据，降低越权和数据副本风险。
- 移除桌面插件入口：手机端不再显示只能在电脑使用的插件入口，减少无效点击。
- 移除重复聊天记录客户端：统一聊天记录读取路径，修复不同页面对同一会话显示不一致的问题。
- 移除固定构建内存限制：手机端构建由工具自动分配内存，减少大型项目构建时因固定上限失败。

安全

- 服务端确认设备身份：客户端不能通过修改请求参数伪造其他设备，跨设备操作的身份来源更可靠。
- 完整执行范围校验：跨设备执行会核对当前 Core、来源设备、目标设备、角色、统筹模式和权限版本，权限变化后旧操作会自动失效。
- 管理员权限不继承：扫码或配对不会自动获得管理员权限，设备转接也不会沿用上一台设备的管理权限。
- 旧入口权限补齐：旧聊天、同步、媒体、语音和反馈入口补齐设备与管理员边界，普通设备不能读取其他设备私有数据。
- 撤权立即生效：远程设备在权限撤销后不能继续读取旧页面、旧任务或旧结果。
- 单次资源审批：审批会绑定执行设备、执行范围、输入摘要和当前连接，避免同一审批被其他任务复用。
- 工具范围隔离：Agent 工具调用携带完整权限范围，参数相同但权限范围不同不能复用执行结果。
- 推送令牌保护：推送令牌不会出现在设备公开信息中，无效令牌会自动清理。
- MCP 凭据保护：凭据加密保存，包含敏感配置的审批不会在应用重启后自动恢复。
- Skill 安全边界：安装 Skill 不会自动执行自带脚本，allowed-tools 只代表能力声明，不会直接获得工具权限。
- 反馈诊断保护：反馈附件和诊断信息需要明确授权后才会随反馈上传。
- 更新签名校验：更新清单经过签名校验，安装包会校验版本、架构、大小和摘要，防止下载到错误或不完整文件。
- 内置运行时校验：手机端会校验运行时清单、源版本和每个载荷摘要，内容不匹配时拒绝更新。
- 附件完整性校验：聊天附件会校验内容类型、图片尺寸、文件签名和 SHA-256；单条消息最多两个附件，每个不超过 1 MiB。
- 媒体临时授权：图片和文件预览使用短期媒体票据，不暴露永久公开地址，票据过期或被替换后不能继续访问。
- Android 安装包限制：手机端只接受正式签名的 arm64-v8a 安装包。
- 发布内容一致性：桌面端安装包、差分文件和更新信息必须来自同一次发布，避免版本信息与安装内容不一致。
- 工作台资源权限：浏览器、终端和工作目录操作需要当前设备身份和对应控制权限，普通只读能力不会自动获得执行权限。
- 工作区命令边界：命令只能在绑定的可写工作区中执行，不能通过相对路径或符号链接逃逸；只读工作区拒绝执行命令。
